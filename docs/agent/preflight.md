# Гейты: перед пушем и перед мержем

Канон двух команд, которые заменяют «не забыть» на «проверено машиной»:

```bash
python scripts/preflight.py            # перед коммитом и пушем
python scripts/check_pr_ready.py 1100  # перед мержем PR
```

Документ отвечает на три вопроса: **зачем гейт вообще** (иначе он воспринимается
как лишний шаг и обходится), **что именно он проверяет** и **что делать, когда
он красный**. Компактный триггер — в [`../../CLAUDE.md`](../../CLAUDE.md);
детали не дублировать там.

---

## Почему не «ещё один пункт в чек-листе»

Разбор сессии 2026-08-13 дал одиннадцать инцидентов. Существенно
здесь то, что **девять из них — не незнание правила, а его пропуск**: правило
«прогонять ВЕСЬ набор» уже было в `CLAUDE.md`, когда профильная выборка молча
сломала чужой тест; правило «ветвиться от свежего main» — тоже, когда гейт
прогнали на устаревшей ветке и `main` покраснел после мержа.

Отсюда принцип, по которому здесь всё устроено:

> **Правило, которое надо вспомнить, соблюдается ровно до первой спешки.
> Правило, которое проверяет команда, соблюдается всегда.**

Поэтому текст чек-листа переписан в код, а не дополнен ещё одним пунктом.
Каждая проверка ниже названа вместе с инцидентом, из которого выросла: правило
без причины выглядит формальностью, и его первым обходят.

## `preflight.py` — перед пушем

| Проверка | Инцидент, из которого выросла |
|---|---|
| ветка не `main` | прямые коммиты в `main` запрещены контрактом |
| **ветка от свежего `origin/main`** | гейт прогнали на ветке, созданной до чужого мержа: локально 18 passed, на `main` красные все девять ubuntu-джобов. «Зелено на моей ветке» ≠ «зелено после мержа» |
| **имя ветки не занято** | дважды взята работа соседнего окна; во второй раз совпало и имя ветки — `push` отлетел «tip is behind», а правка чуть не уехала в чужой PR |
| пересечение файлов с чужими ветками | общие файлы расходятся конфликтами, и узнаётся это в момент мержа (`check_work_overlap.py`) |
| **запись в `## Буфер` CHANGELOG** | требуется в каждом PR, но CI её не проверяет — держалась на памяти и чек-листе |
| карта «кто ссылается на правку» | тестовый файл искали по угаданному имени, не нашли, положили тесты в другой файл — и молча сломали `test_loader.py`. `grep` по имени функции ищет тех, кто патчит наши имена |
| один прогон за раз (`.git/preflight.lock`) | два параллельных `pytest` исчерпали дескрипторы: 72 «падения», все средовые (`OSError WinError 6/50` в тестах с subprocess). Полдня разбора регрессии, которой нет |
| весь набор + **вывод целиком в файл** | `pytest … \| tail -8` в фоне отбросил всё, кроме хвоста, и шестиминутный прогон пришлось повторять. Скрипт всегда пишет полный лог в `.git/preflight-logs/` |
| `ruff check` · `ruff format` · `mypy` | зеркалит CI, чтобы красное находилось до пуша, а не в матрице |

Режимы:

```bash
python scripts/preflight.py                # всё, включая полный pytest
python scripts/preflight.py --branch-only  # только гигиена ветки — ДО начала работы
python scripts/preflight.py --no-tests     # правки только в докáх
python scripts/preflight.py --force-lock   # перехватить протухшую блокировку
python scripts/preflight.py --install-hook # pre-push хук, отклоняющий непроверенный коммит
```

`--branch-only` дешёвый и запускается **до** работы, а не после: он отвечает на
вопрос «эту задачу уже кто-то делает?» тогда, когда ответ ещё что-то меняет.

### Штамп и pre-push хук

Удачный прогон пишет `.git/preflight-stamp.json` с SHA проверенного коммита.
Хук (`--install-hook`) сравнивает штамп с текущим `HEAD` и отклоняет пуш, если
уехать собирается **не то состояние, которое проверяли**. Аварийный выход —
`PREFLIGHT_SKIP=1 git push …`: он существует для срочного фикса там, где прогон
физически негде сделать, и остаётся осознанным решением человека, а не
значением по умолчанию.

## `check_pr_ready.py` — перед мержем

Инцидент: PR смержили, когда **9 проверок из 14 были `queued`/`in_progress`**.
Проверка звучала разумно — «нет `failure` и нет `pending` → мержим», — но сразу
после `git push` GitHub ещё не успевает создать check-runs, и REST отдаёт
**пустой список**. На пустоте это условие выполняется идеально.

Три правила, закодированные в скрипте:

1. **Пустой или неполный список проверок — «CI не стартовал», а не «зелено».**
   Поэтому смотрится не только `/commits/{sha}/check-runs`, но и
   `/actions/runs?head_sha=…`: пока прогон в `queued`/`in_progress`, часть
   джобов ещё не существует, и судить по ним нельзя.
2. **Набор сверяется с эталоном** — именами проверок последнего коммита `main`.
   Эталон живой, а не константа в коде: список джобов меняется вместе с
   `ci.yml`, и зашитое число устарело бы молча.
3. **Только REST.** `gh pr view` / `gh pr checks` ходят через GraphQL, и поллинг
   в цикле выжигает квоту 5000/час до нуля — посреди работы `gh` просто
   перестаёт отвечать, со сбросом через полчаса. Опрашивать не чаще, чем раз в
   45–60 секунд.

```bash
python scripts/check_pr_ready.py 1100          # вердикт: 0 — можно мержить
python scripts/check_pr_ready.py 1100 --json   # то же машинно
```

Транспорт: `gh api` (локальное окно, где `gh` уже авторизован), иначе прямой
REST с `GH_TOKEN`/`GITHUB_TOKEN` из окружения.

## Что гейты не ловят — и почему это записано здесь

Три инцидента той же сессии механической проверке не поддаются; они остаются
правилами, но названы явно, чтобы не выглядели «и так понятно»:

- **Пуш в ветку чужого PR.** Конфликт локалей выглядел тривиальным («оставить
  обе строки»), и правку внесли прямо в ветку соседнего окна. Гейт видит только
  совпадение имени ветки, а не намерение. Правило: **в чужую ветку не пушить** —
  сообщить владельцу, что и как разрешать.
- **Escape-последовательности через bash-heredoc.** `\n` внутри Python-строки,
  записанной heredoc'ом, дважды превращался в настоящий перевод строки →
  `SyntaxError: unterminated string literal`. Правило: код с экранированием
  писать **файлом**, а не heredoc'ом.
- **«Тест краснеет до фикса», доказанное откатом всего `src/`.** Тесты падали на
  `ImportError` — то есть доказано лишь «тест ссылается на новый код». Правило:
  краснота проверяется **полу-откатом** — новые имена оставить, убрать только
  поведение.

## Порядок работы целиком

```
1. python scripts/preflight.py --branch-only   # до работы: чужая ли это задача, свободно ли имя
2. … правки, тесты …
3. python scripts/preflight.py                 # перед коммитом: весь набор + линтеры + типы
4. git push -u origin <branch>                 # хук пропустит только проверенный коммит
5. python scripts/check_pr_ready.py <PR>       # перед мержем: набор полон, всё зелёное
```

Связанное: [`environments.md`](environments.md) — что из этого вообще выполнимо
в облачном окне, а что только на локальной машине;
[`../../CONTRIBUTING.md`](../../CONTRIBUTING.md) § «Когда дефект считается
исправленным» — критерий приёмки фикса.
