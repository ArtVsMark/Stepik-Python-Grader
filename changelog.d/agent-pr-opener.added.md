Конвейер открывает PR сам: workflow `agent-pr.yml` и `scripts/open_agent_prs.py` заводят PR для веток `agent/**` и включают им авто-мерж, а заголовок и тело берут из сообщения последнего коммита — того самого, что уедет в squash. Это был единственный шаг, где конвейер упирался в человека: облачная сессия не может открыть PR от своего имени (прокси подменяет учётные данные, и автором становится бот, а такой PR мерж-гейт не пропускает намеренно — squash записал бы бота автором в `main` навсегда), поэтому PR создаётся внутри Actions токеном владельца. Триггера два, пуш и расписание: пуш из облака идёт учётными данными приложения и разбудить workflow не обязан. Ветка с уже открытым PR и ветка без коммитов сверх `main` пропускаются — при двух триггерах это не теория. Гейт `check_workflow_guardrails.py` держит, что открыватель ходит своим токеном: с `GITHUB_TOKEN` автором станет бот, и механизм сломается ровно там, ради чего заведён (#1302)
