Запись о изменении делается файлом `changelog.d/<slug>.<секция>.md`, а не строкой в общий `CHANGELOG.md`: два файла с разными именами не конфликтуют, поэтому параллельные PR перестали делать друг друга `dirty` — а конфликтный PR оставался вовсе без проверок, потому что прогон идёт по несуществующему merge-коммиту. Сборка при релизе — `python scripts/collect_changelog.py --collect` (#1116)
