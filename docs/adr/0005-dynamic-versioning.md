# ADR-0005 — Версия пакета: динамическая из git-тегов (setuptools-scm)

## Контекст

Проект использует **собственную (не-SemVer) схему** (issue #68): git-тег
ставится только на границе MINOR, поэтому **все теги имеют вид `vX.Y.0`**, а
PATCH — это счётчик коммитов после последнего тега (не номер патч-релиза).

Раньше `version` объявлялась статической строкой в `pyproject.toml` и правилась
вручную. Это стабильный источник дрейфа: строка в `[project]`, последний
git-тег, README-бейдж и `CHECKPOINT.md` регулярно расходились, а забытый bump
при релизе ловился только постфактум.

`setuptools-scm` умеет выводить PEP 440-версию прямо из git-тегов, но **не
умеет** «складывать коммиты в PATCH» именованной схемы проекта — его post-release
формат даёт `X.Y.0.postN+g<hash>`, а не `X.Y.N`.

## Решение

1. **`version` — dynamic, вычисляется `setuptools-scm` из git-тегов.**
   `dynamic = ["version"]`, `version_scheme = "post-release"`. Статической строки
   `version` в `[project]` **нет**; править вручную нельзя.
2. **Две формы одного номера сосуществуют, обе от setuptools-scm (валидный
   PEP 440):**
   - **Release** — HEAD ровно на теге: `X.Y.0` (то, что уходит на PyPI/Release).
   - **Dev** — N коммитов после тега: `X.Y.0.postN+g<hash>` (технически
     отличимая пост-релизная сборка).
3. **Логический человекочитаемый счётчик `X.Y.N`** (README-бейдж «Version») —
   отдельный инструмент [`scripts/version.py`](../../scripts/version.py): «тег +
   число коммитов», **не PEP 440** и не метаданные пакета; исключает CI-автокоммиты
   бейджей `chore(ci): … [skip ci]` из счёта (issue #231), иначе счётчик рос бы
   вдвое быстрее реальных изменений.
4. **За дрейф отвечает CI, не человек.**
   [`scripts/check_version_consistency.py`](../../scripts/check_version_consistency.py)
   (issue #165) мягко предупреждает при расхождении `| Версия |`
   (CLAUDE.md/README) и `Текущая версия:` (CHECKPOINT) с последним тегом. Ручная
   сверка версий больше не нужна.

## Альтернативы

- **A. Статическая `version` + ручной bump (status quo до #162).** Минус:
  систематический дрейф, забытый bump, merge-конфликты по одной строке.
  Отклонено — это и есть устраняемая боль.
- **B. `bump2version` / `commitizen`.** Минус: всё равно материализуют версию в
  файле (тот же дрейф), заточены под SemVer и чужды кастомной схеме `vX.Y.0`.
  Отклонено.
- **C. `setuptools-scm`, git — единственный источник (выбрано).** PEP 440
  выводится из тегов, ноль ручных правок, дрейф стережёт CI. Логическая схема
  остаётся отдельным справочным счётчиком.

## Последствия

**Положительные:**

- Единственный источник истины — git-тег; нельзя забыть или переврать bump.
- Сборки вне тега технически отличимы (`.postN+g<hash>`) — видно, что это не
  официальный релиз.
- Ручная сверка версий заменена CI-проверкой (#165).

**Отрицательные / издержки:**

- Для корректной версии при сборке нужны git и теги: в shallow-clone или
  tarball-архиве без `.git` версия деградирует (setuptools-scm fallback) — это
  известное ограничение подхода.
- Сосуществование двух форм номера (PEP 440 vs логический `X.Y.N`) требует
  объяснения — оно вынесено в [CONTRIBUTING.md § Версионирование](../../CONTRIBUTING.md#версионирование-issue-68).

**Нейтральные:**

- MINOR-bump = новый тег `vX.Y.0`; PATCH существует только как счётчик коммитов,
  отдельных PATCH-релизов не публикуется.
