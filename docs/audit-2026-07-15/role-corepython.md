### Сильные стороны

- **Идиоматика 3.12+ реально соблюдается**: union-типы везде (ноль `Optional`/`List`/`Dict`), `tomllib`, frozen dataclasses c `field(default_factory=...)`, `Protocol` + `@runtime_checkable` (`core/runner.py:112`, провайдеры glossary/rules), PEP 562 ленивый `CONFIG` через module-level `__getattr__` (`config.py:164`), `argparse.BooleanOptionalAction`, `sys.executable` для subprocess — без исключений.
- **Packaging — образцовый по существу**: PEP 621 + PEP 639 (SPDX `license` + `license-files`), PEP 561 (`py.typed` в package-data), динамическая версия setuptools-scm с PEP 440-корректной схемой `X.Y.0.postN+g<hash>`, pytest11 entry point, opt-in extras (`watch`/`e2e`/`lint`) вместо раздувания runtime-зависимостей (их всего 3).
- **Готовность к 3.14 — высокая**: CI уже гоняет 3.14 experimental (ubuntu); мой AST-скан не нашёл `return`-в-`finally` (PEP 765); нет `multiprocessing` (смена дефолта на forkserver не задевает), нет удалённых модулей/`utcnow`/`ast.Str`; `from __future__ import annotations` во всех файлах совместим с PEP 749. `wrapper_builder.py:74-78` даже документирует ловушку PEP 709/667 с `locals()` в comprehension — редкая глубина.
- **Subprocess-гигиена в poll-пути**: `LocalRunner._run_with_polling` и `_posix_common.run_argv_with_limits` корректно дренируют пайпы фоновыми потоками с bounded `join`, stdin пишется до цикла ожидания — классический deadlock переполненного pipe-буфера осознанно исключён; `RLIMIT_AS` через `prlimit` после spawn вместо документированно небезопасного `preexec_fn` в многопоточном родителе (`runner.py:126-151`).
- `pytest_plugin.py` — грамотный: ленивые импорты ядра с внятным объяснением (entry-point грузится до coverage), `from_parent`, читаемый `repr_failure`; осознанный omit из coverage с обоснованием.

### Находки

**F1 (high) — `LocalRunner`: kill не убивает группу процессов; `communicate()` после kill блокируется на пайпе внука.** `core/runner.py:262-264`: при `TimeoutExpired` вызывается `proc.kill()` (только прямой ребёнок) и затем `proc.communicate()` без таймаута. Внук, унаследовавший stdout/stderr, держит pipe открытым — `communicate()` ждёт EOF. Воспроизведено: решение, спавнящее `sleep(8)` и зависающее, при `timeout=2.0` вернуло управление через **8.1 с**; демонизированный внук = вечное зависание грейдера/синхронного `/api/grade`/`/api/playground` (там `cancel_event=None` → именно этот путь). Плюс внуки-сироты продолжают жить (утечка ресурсов). Лечение: `start_new_session=True` + `os.killpg` на POSIX (на Windows у проекта уже есть Job Objects в `core/sandbox/_windows.py` как прецедент), и bounded `communicate(timeout=...)` после kill.

**F2 (medium) — `executor.py`: exec-namespace без `__name__`/`__file__` — main-guard молча не выполняется.** `core/executor.py:167`: `namespace = {"__builtins__": builtins}`. Лукап `__name__` проваливается в модуль builtins и возвращает `"builtins"` — блок `if __name__ == "__main__":` в решении **тихо пропускается** (проверено: печатается только код вне guard, rc=0, без ошибки). `tracer.py:205` делает правильно (`{"__name__": "__main__", "__file__": target_file}`) — внутрипроектная непоследовательность. `run_solution` — публичный API (`__all__`, реэкспорт фасада), хоть сегодня и вызывается только тестами.

**F3 (medium) — mypy фактически на минималках, хотя код готов к строже.** Секции `[tool.mypy]` нет вообще; CI — `mypy --ignore-missing-imports`. Замер: `--disallow-untyped-defs --disallow-incomplete-defs` — **0 ошибок уже сейчас**; полный `--strict` — всего 42 (24 `attr-defined` — реэкспорты фасада `grader.py`, лечатся `implicit_reexport`-политикой; 9 `no-any-return` — `normalizers.py:41` (`re.Match` без параметра типа), `cli/options.py:249/264/276`, `diagnostic_stepik.py:108-126`; 9 `unused-ignore` — платформозависимы, глобально не включать). Дешёвый и большой выигрыш строгости не зафиксирован конфигом — уровень проверки зависит от строки в CI.

**F4 (medium) — контракт результата — стрингли-typed `dict[str, Any]`.** `run_single_test` (`grader_core.py:239`), `_fail_result`, весь web-слой: 159 вхождений `dict[str, Any]` при том, что форма case-result формально специфицирована в `docs/result-contract.md`. Ни одного `TypedDict` в проекте. `CaseResult(TypedDict)` дал бы проверку ключей/типов mypy'ем по всей цепочке CLI→web→pytest-плагин (в `pytest_plugin.GraderFailure.result` — тот же словарь) без изменения runtime-представления.

**F5 (low) — 14 нарушений собственного pathlib-инварианта, не автоматизированного линтером.** CLAUDE.md требует «только pathlib», но ruff-select (`E,F,W,I,UP,B,S102`) не содержит `PTH`: `open()` вместо `Path.open` (`core/storage.py:35,45`, `core/stats.py:102`, `glossary/json_provider.py:136,193,217`, `rules/json_provider.py:113`), `os.unlink` ×5 (`grader_core.py:323`, `tracer.py:303`, `web/runs.py:299`, `web/playground.py:74`, `microbench_runner.py:251`), `os.chmod` (`storage.py:68`). Заодно: 11×SIM105, 2 реально мёртвых `noqa: F401` (`grader_core.py:67,97`, ловится RUF100).

**F6 (low) — несогласованные тайм-ауты и мёртвый API в `executor.py`.** Параметр `run_solution(stdin=...)` объявлен/задокументирован, но молча игнорируется (`executor.py:128`); параметр `timeout` управляет только `subprocess.run`, а SIGALRM ребёнка всегда ставится по модульному `TIMEOUT` — `run_solution(..., timeout=30)` всё равно прервётся изнутри на 10-й секунде. `signal.alarm` — целые секунды (для float есть `setitimer`). Поле `RunResult.extra` никогда не заполняется (только тесты проверяют, что оно пустое) — YAGNI.

**F7 (low) — packaging-метаданные для PyPI пустые.** В `[project]` нет `classifiers` (включая `Programming Language :: Python :: 3.12/3.13`), `authors`, `keywords`, `[project.urls]` (Homepage/Repository/Changelog) — при публикации карточка пакета будет голой. Плюс `[tool.setuptools.package-data]` нерекурсивен и уже дважды кусался (issue #260 fonts, #265 vendor) — каждый новый подкаталог `static/` требует помнить про паттерн.

**F8 (low) — `load_config()` не валидирует типы TOML-переопределений.** `config.py:144`: `timeout_seconds = "10"` в `[tool.stepik-grader]` молча создаст `GraderConfig(timeout_seconds="10")` (frozen dataclass не проверяет типы) и упадёт позже произвольной арифметикой глубоко в grading-пути, а не понятной ошибкой на загрузке конфига.
