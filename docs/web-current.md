>    исполнение с трассировкой и визуализацией связей переменных, панель

## Цель WEB MVP

WEB MVP — это **локальная оболочка поверх существующего ядра и CLI**, а не
новый продукт. Цели:

1. **Снизить барьер входа.** Консольное меню (`stepik-grader`, режимы 0–7) —
   препятствие для новичков и тех, кто работает из IDE. Веб-оболочка даёт то
   же самое в браузере: указал путь → увидел вердикты AC/WA/TLE/RE, diff,
   бенчмарк.
2. **Связать проверку с обучением.** Когда решение падает, рядом открывается
   карточка глоссария по типу ошибки
   ([Glossary-Python](https://github.com/ArtVsMark/Glossary-Python), issue
   #72 / эпик #96).
3. **Не ломать `--serve`.** Эндпоинт `/api/grade` остаётся обратно
   совместимым — см. [api.md](api.md) для полного справочника.

**Принцип неинвазивности.** Ядро (`core/grader_core.py`,
`core/test_loader.py`, …) остаётся библиотекой. Веб-слой вызывает те же
публичные функции, что и CLI (`run_tests`, `run_benchmark`,
`apply_relative_ranking`, `lookup_from_error`) — новой бизнес-логики
грейдинга в web UI нет (см. [architecture.md](architecture.md), ребро
`web → core` ациклично).

## Разделы и функциональные блоки

Оболочка делится на **шесть разделов навигации** (sidebar): «Проверка
решений», «Загрузчик задач», «Глоссарий», «Правила (PEP)», «Подучить»,
«Песочница».

| Блок | Раздел UI | Что делает | Источник данных |
|---|---|---|---|
| **Проверка решений** | Проверка решений | Прогон файла/папки на корректность (режимы 1/2), subprocess-бенчмарк (режим 3) и микро-бенчмарк timeit (режим 4); таблица вердиктов, diff при WA, error cards при RE/TLE. Панель **«Функции в коде»** (issue #323/#367): мини-карточки функций/методов/конструкций текущего решения (только режим 1, по коду редактора с debounce — issue #366/#324), клик → полная карточка глоссария. Наборы builtins/методов — из stdlib-инвентаря (issue #367), плюс синтаксические конструкции и корректный разбор `os.path.join` (≠ `str.join`) | `grade_path()` / `grade_benchmark()` / `grade_microbench()` → `run_tests` / `run_benchmark` / `run_microbench_mode`; мини-карточки — `POST /api/code-terms` |
| **Downloader / Загрузка тестов** | Загрузчик задач (отдельный раздел) | По URL шага Stepik скачивает задачу, шаблоны и тест-кейсы в локальную папку, откуда сразу можно запустить проверку | `web/downloader_adapter.py::download_task()` — тонкий адаптер над `downloader.py::process_step_url` + `core/oauth_flow.py::try_create_session_without_browser` |
| **Глоссарий** | Глоссарий | Локальный knowledge-модуль: карточки терминов/исключений/функций в проекте, поиск, детектор недостающих конструкций, очередь пополнения | `GlossaryProvider`/store (#126) поверх `core/glossary.py`; `MissingConceptDetector` |
| **Песочница** | Песочница | Не проверка, а «запусти этот код с этим вводом»: редактор + поле stdin + вывод (stdout/stderr, код выхода, время). Статусы OK/RE/TLE/CANCELLED (issue #317). Кнопка **«Пошагово»** (issue #319) открывает плеер трейса: ⏮◀▶⏭ + слайдер + ←→, подсветка активной строки в снимке кода, кадры стека с переменными (изменившиеся подсвечены), нарастающий вывод, красная строка + ссылка в глоссарий на шаге-исключении. Переключатель **«Таблица / Диаграмма»** (issue #320) рисует memory-graph в духе Python Tutor: кадры слева, узлы heap-объектов справа, SVG-стрелки переменная→объект (aliasing = две стрелки в один узел, вложенность = стрелки узел→узел). Панель **«Функции в коде»** (issue #321): мини-карточки функций, найденных в коде (debounce), клик → полная карточка глоссария; при RE — error card с типом исключения и deep-link в глоссарий | `web/playground.py::run_playground()` (playground) и `core/tracer.py::trace_code()` (trace) поверх `core/runner.LocalRunner`; async через `POST /api/v1/runs` `mode="playground"`/`"trace"`; мини-карточки — `POST /api/code-terms` (`glossary_adapter.code_terms` над `scan_code_concepts`) |

> **Разделы «Правила» и «Подучить» (эпик #342, issue #348).** «Правила (PEP)» —
> list+detail карточек правил (поиск, фильтр-чипы по тегам, deep-link
> `#/rules/<code>`, примеры «до/после»); «Подучить» — карточки частых ошибок со
> статусом затухания (🔥 активна / 🌤 угасает / ✅ архив) + ссылки на
> глоссарий/правила и бейдж активных в sidebar (deep-link `#/insights`). Данные
> — `GET /api/rules` (`?q&tag`) / `/api/rules/{code}` / `GET /api/insights` (см.
> [api.md](api.md)) поверх `rules/` (#345) и `core/insights` (#347). Те же
> инсайты в терминале — `--insights`/`--lint` (#349). Единый hash-роутер
> (замена glossary-only, риск R6). Чипы «Стиль» прямо в результатах проверки
> (lint в web-grade) — отдельный follow-up.

Блоки связаны:

- из **error card** в «Проверке решений» есть переход **Open glossary**
  прямо на нужную карточку раздела «Глоссарий» (deep-link по `glossary_id`);
- **Downloader** — кнопка «Перейти к проверке» (по клику, не автоматически)
  подставляет скачанный путь в command bar «Проверки решений» и переключает
  раздел — скачал → сам нажимает ▶ (J0);
- **детектор недостающих концепций** глоссария читает решения/ошибки из
  «Проверки решений» и пополняет очередь карточек.

Обратной жёсткой связи нет — «Глоссарий» самодостаточен и может читаться
отдельно.

## Downloader / Загрузка тестов

Скачивание задачи и тест-кейсов из Stepik — реализовано в issue #186 как
отдельный раздел «Загрузчик задач». CLI-путь
(`python -m stepik_grader.downloader`, см.
[grader-workflow.md § Шаг скачивания задачи](grader-workflow.md#шаг-скачивания-задачи))
остаётся неизменным и по-прежнему единственный способ выполнить первичную
OAuth-авторизацию — веб-раздел лишь показывает понятную ошибку, если
валидного токена нет.

**Где в UI.** Отдельный раздел «Загрузчик задач» (sidebar, `data-section=
"downloader"`, `<section id="view-downloader">`): поле URL шага, поле
корневой папки (опционально, по умолчанию `StepikTasks`/значение из
`stepik_config.json`), кнопка «▶ Скачать». По завершении — кнопка «Перейти к
проверке» (по клику, не автоматически) подставляет путь скачанной папки в
поле пути раздела «Проверка решений» и переключает раздел — цикл «скачал →
сам нажимает ▶ проверки» замыкается без копипаста (J0).

**Что показывает.** Итог загрузки (`DownloadedTask`): какие файлы созданы
(`task{N}_1.py`, `tests/`, `task.md`, `meta.json`), сколько тест-кейсов
извлечено и из какого источника (ZIP / HTML-таблица / GitHub-ссылка / ничего
не найдено — те же 4 приоритета, что в `downloader.py`).

**Границы (неинвазивность).** Web-слой (`web/downloader_adapter.py`) — тонкий
адаптер над публичными функциями `downloader.py`/`core/oauth_flow.py`; новой
логики скачивания в web нет, DAG без циклов сохраняется (`web →
downloader → core`).

**OAuth.** Требует настроенного `secrets.json`
([installation.md](installation.md#работа-с-api-stepik-oauth)). Браузерный
OAuth-редирект **не реализован и не планируется для веб-раздела** — первичная
авторизация остаётся за CLI (`downloader`/`diagnostic_stepik`);
`try_create_session_without_browser` проверяет валидный токен/обновляет по
`refresh_token`, а если ни один путь не сработал — веб-раздел показывает
понятную ошибку «нужна авторизация» со ссылкой на `installation.md`.

**Non-goal.** Массовое/batch-скачивание курса целиком, планировщик
обновлений — вне рамок; один шаг за раз, как в CLI.

## Режимы проверки и микро-бенчмарк

CLI поддерживает **четыре** рабочих режима (плюс `0` — выход); WEB отражает
все четыре, включая корректность, subprocess-бенчмарк и микро-бенчмарк:

| Режим CLI | Название | Ядро | Раздел UI «Проверка решений» |
|---|---|---|---|
| 1 | Проверка одного файла | `run_tests` | режим **Корректность** (файл) |
| 2 | Проверка папки | `run_tests` | режим **Корректность** (папка) |
| 3 | Subprocess-бенчмарк | `run_benchmark` | режим **Бенчмарк** |
| 4 | Микро-бенчмарк (timeit) | `run_microbench_mode` | режим **Микро-бенчмарк** |

Переключатель режимов — ряд кнопок **«Режим 1…4»** (Один файл / Папка /
Bench / Microbench) в шапке раздела «Проверка решений». Микро-бенчмарк
(режим 4) меряет время через `timeit` внутри процесса и показывает колонки,
отличные от режима 3:

- метрики в **микросекундах** (`Min/Median/Mean/Max/Std dev, µs`),
  `Relative`, `Verdict` (`SIMILAR`/`SLOWER`/`MUCH SLOWER`);
- колонка памяти называется **`Py-heap`** (не `Memory`): для stdin-блоков —
  пик Python-heap через `tracemalloc`, для function-блоков — RSS (issue #66);
- профили «calls per run» (fast/normal/thorough/deep/hard/custom) —
  параметр запуска (аналог `--number`).

**Реализовано (issue #187).** `grade_microbench()` + `_resolve_group_test_dir`
(`web/viewmodels.py`), роутинг `mode=microbench` (`server.py`,
`GET /api/grade?mode=microbench&number=`, см. [api.md](api.md)),
профиль-селектор и таблица результатов — всё реализовано, оркестрация —
`core/grader_core.py::run_microbench_mode`, нижнеуровневый прогон —
`core/microbench_runner.py::run_microbench`. Non-goal: менять саму методику
timeit-замера — web лишь отображает результат существующего ядра.
Per-block detail-разбор (какой блок замерялся stdin/tracemalloc vs
function/RSS) остаётся design-only, см.
[web-design.md](web-design.md#per-block-detail-разбор-микробенча).

## Глоссарий как локальный knowledge-модуль

Раздел «Глоссарий» — **не список внешних ссылок**. Внутри
Stepik-Python-Grader живёт полноценный локальный knowledge-модуль, который
хранит контент и обнаруживает пробелы. Внешний проект
[Glossary-Python](https://github.com/ArtVsMark/Glossary-Python) при этом
**сохраняется** как отдельный лёгкий one-page HTML-справочник для быстрого
доступа откуда угодно — он не заменяется, а получает контент через экспорт
(design-only, см. [web-design.md](web-design.md#экспортсинхронизация-глоссария-во-внешний-проект)).

**Составные части модуля:**

1. **Локальная база карточек** (`GlossaryProvider`/store, #126). Карточки
   терминов/исключений/функций хранятся **в проекте** — JSON-файл(ы), при
   росте — SQLite. Расширяет компактный `core/glossary.py` (~28 исключений)
   полями `body`/`section`/`related`/`status` (см. контракт `GlossaryCard`).
   Источник истины для карточек — локальная база, а не удалённый сайт.
2. **Детектор недостающих концепций** (`MissingConceptDetector`). Сканирует
   решения (AST/имена), тексты ошибок и вердикты RE/WA и находит
   функции/конструкции/исключения, для которых **нет карточки** в локальной
   базе (например, встретился `functools.reduce`, `RecursionError` без
   карточки, конструкция `match/case`).
3. **Очередь пополнения** (backlog недостающих карточек). Обнаруженные
   пробелы складываются в локальную очередь `GlossaryMissingEntry` со
   статусом `new` — черновики для последующего наполнения (вручную или
   полуавтоматически). Это «TODO-лист глоссария», который растёт из реальной
   практики проверки решений.
4. **Связь с error cards и проверкой решений.** error card при RE/WA
   ссылается на карточку глоссария (`glossary_ids`), а если карточки нет —
   `MissingConceptDetector` регистрирует пробел в очереди. Так глоссарий
   пополняется именно теми терминами, на которых спотыкаются решения.
5. **UI раздела (issue #329).** Комплектная база (581 карточка, #326) грузится
   по умолчанию (zero-config). Поверх списка — тулбар: поиск, быстрые
   чипы-разделы (**«Списки», «Кортежи», «Словари», «Множества»** — отдельными
   чипами, разнотипное не объединяется), селект раздела, фильтр по типу
   (`kind`) и сортировка (A–Я / по разделам / по версии) — грани комбинируются
   на бэке (`GET /api/glossary`, см. [api.md](api.md#get-apiglossary)); счётчик
   «Показано N из M». Карточка открывается по deep-link `#/glossary/<id>`
   (прямые ссылки; сюда же ведут error cards и, позже, мини-карточки «Функции
   в коде», #323). Полный вид карточки рендерит `syntax`, примеры,
   version-бейдж и ссылку на docs.python.org (#325).

**Жизненный цикл карточки:** `new` (обнаружена детектором) → `draft`
(наполняется) → `ready` (готова к показу/экспорту) → `exported`
(выгружена во внешний глоссарий — экспорт сам ещё design-only, см. ниже).

**Двуязычные описания (issue #363).** Текстовые поля `summary` и `body`
хранятся двуязычно — вложенным `{ru, en}` в JSON. Web-API (`/api/glossary`,
`/api/glossary/<id>`, `/api/code-terms`) отдаёт их **строкой** локали из
`?lang=` (селект «Язык интерфейса» в «Настройках», #364) с fallback на `ru`;
смена языка перезагружает список и открытую карточку без перезагрузки страницы.
Python-атрибуты `card.summary`/`card.body` остаются RU-строками (обратная
совместимость всех читателей), EN — `card.summary_en`/`card.body_en`;
локализация в API — `card.localized(field, lang)` / `card.to_api_dict(lang)`.

**Разделение ролей (важно):**

| | Локальный модуль (Stepik-Python-Grader) | Внешний Glossary-Python |
|---|---|---|
| Роль | Богатый learning/checking-глоссарий: база карточек, детектор пробелов, очередь, связь с проверкой | Лёгкий one-page HTML-справочник для быстрого доступа откуда угодно |
| Данные | Локальная JSON/SQLite-база в проекте | Статический HTML/GitHub Pages |
| Направление | Источник контента → экспорт наружу | Потребитель экспортированных карточек |
| Обновление | Растёт из реальной практики проверки решений | Обновляется экспортом из грейдера |

Внешний проект **не** заменяет локальный модуль и **не** редактируется из
грейдера напрямую (см. запрет в [`../CLAUDE.md`](../CLAUDE.md) § «Связанный
проект») — только через экспорт/PR в самом Glossary-Python.

**Истина контента vs истина полноты.** Важно не смешивать два разных вопроса:

- **Где хранится контент** — источник истины контента — сам
  **Stepik-Python-Grader** (локальная база карточек). Glossary-Python —
  downstream-витрина/цель экспорта, **никогда** не эталон.
- **Относительно чего меряется полнота (coverage)** — источник истины полноты —
  **официальный Python / stdlib**. «Чего не хватает» считается относительно
  официального языка и стандартной библиотеки, а не стороннего справочника.

Отсюда **два источника пробелов** очереди пополнения: *practice-driven* (из
решений/ошибок, детектор — J7 ниже) и *source-driven* (сканирование покрытия
stdlib, `glossary/stdlib_inventory.py`/`coverage.py`). Роли и источники
канонично сведены в
[glossary.md § Источники истины](glossary.md#источники-истины-роли).

## Layout: split-pane workspace

Раздел «Проверка решений» — двухпанельное рабочее пространство (`.split-pane`,
`1fr 1fr`): слева конфиг-панель, справа панель результатов. В режимах 3/4
(bench/microbench) раскладка переключается на **вертикальный стек**
(`.split-pane--stacked`, issue #370): конфиг компактной полосой сверху,
панель результатов — во всю ширину под ним.

```
┌─────────────┬───────────────────────────┬───────────────────────────┐
│  SIDEBAR    │  CONFIG PANEL             │  RESULT PANEL             │
│ (навигация) │  (без вкладок)            │  вкладки: Таблица / Разбор │
│             │  • путь + datalist        │  • Таблица решений         │
│             │    недавних путей         │    (passed / verdict / t)  │
│             │  • параметры 3/4 инлайн    │  • Разбор: Ожидалось/      │
│             │  • редактор кода (р.1)     │    Получено, diff, error   │
│             │  • «Функции в коде» (р.1)  │    card, glossary, ▸ сырой │
└─────────────┴───────────────────────────┴───────────────────────────┘
```

- **Sidebar** — глобальная навигация по разделам (не часть `.split-pane`).
- **Config panel** (левая колонка, **без вкладок** — issue #366): путь с
  datalist-подсказками недавних путей, параметры режимов 3/4 инлайн под полем
  пути (repeats/микро-профиль), редактор кода и панель «Функции в коде» — только
  в режиме 1 (issue #366/#324; в режиме 2 путь — папка, панель пустует).
- **Result panel** (правая колонка) — вкладки «Таблица / **Разбор**» (issue
  #368: «Детали»+«Лог» объединены, «Эталон» удалён — issue #369). **«Разбор» —
  это вкладка, а не отдельная третья колонка**: ядро — сравнение «Ожидалось/
  Получено» (для WA двухколоночно) + diff, error card, glossary card;
  сырой stdout/stderr — коллапсируемая секция внизу. Action cards режима 2 —
  только копирование входа/выхода (`run_again` остаётся в палитре Ctrl+K).
- Таблицы режимов 3/4 — единая структура как в CLI-репортере (Файл/Runs/Min/
  Median/Mean/Max/Std dev/Память/%/Вердикт, issue #370).
- Разделитель панелей **не перетаскивается**; на узком экране панели
  схлопываются в вертикальный стек.

Раздел «Глоссарий» использует тот же `.split-pane` в варианте «список
карточек | панель карточки»; «Загрузчик задач» и «Песочница» — свои
двухпанельные раскладки.

## User journeys

### J0. Скачать задачу и тесты из Stepik, затем проверить

1. Отдельный раздел sidebar **«Загрузчик задач»** → форма загрузки.
2. Ввести URL шага (`https://stepik.org/lesson/.../step/...`), выбрать
   корневую папку (по умолчанию `StepikTasks`), нажать ▶.
3. Downloader создаёт папку задачи (`task{N}_1.py`, `tests/`, `task.md`,
   `meta.json`) и извлекает тест-кейсы; UI показывает, сколько кейсов и из
   какого источника (ZIP / HTML-таблица / GitHub-ссылка / не найдено).
4. По кнопке **«Перейти к проверке»** (по клику, **не автоматически**) путь
   скачанной папки подставляется в поле пути раздела «Проверка решений» и
   происходит переход туда → пользователь нажимает ▶ (J1/J2).
5. Если нет авторизации — понятная ошибка «нужен OAuth» со ссылкой на
   [installation.md](installation.md#работа-с-api-stepik-oauth) (первичный
   OAuth выполняется через CLI).

### J1. Запустить проверку и увидеть AC

1. Открыть `stepik-grader --serve`, раздел «Проверка решений».
2. В command bar — путь к файлу/папке (по умолчанию — папка запуска), режим
   «Корректность», Enter / кнопка ▶.
3. Result panel: строка(и) со статусом **OK**, passed `N/N`, время, память.
4. Клик по строке → detail panel с раскладкой тест-кейсов (все AC).

### J2. Увидеть WA и разобраться

1. J1, но одно решение — **FAIL**.
2. Клик по строке → detail panel показывает тест-кейсы; непрошедший помечен
   **WA**.
3. Под ним — сравнение `expected` / `actual` (diff), stdin кейса, коллапс
   сырого вывода (вкладка «Разбор», #368).
4. Action cards (режим 2): **Copy input**, **Copy output**. Повтор — команда
   **Run again** в палитре Ctrl+K (#368).

### J3. Увидеть RE и открыть карточку глоссария

1. Решение падает с исключением → вердикт **RE**.
2. error card показывает трейсбек (stderr, exit code) и — по
   `lookup_from_error()` — блок глоссария: тип исключения + однострочный hint.
3. Ссылка «открыть карточку в глоссарии →» внутри error card (и команда
   **Open glossary** в палитре) → раздел «Глоссарий», карточка
   (напр. `RecursionError → #recursionerror`), без ухода из оболочки.
4. Команда **Explain error** (палитра в режиме 2, action card в режиме 1) —
   разворачивает hint + типичные причины inline, не переключая раздел.

### J4. Увидеть TLE

1. Решение не укладывается в таймаут (`CONFIG.timeout_seconds`) → вердикт
   **TLE**.
2. error card: severity `warning`, поле `timeout_s`, частичный stdout,
   подсказка «превышен лимит времени; проверьте сложность алгоритма».
3. Команда **Run again** (повторить) — action card в режиме 1, палитра Ctrl+K
   в режиме 2 (#368).

### J5. Скопировать → исправить → повторить

1. В любой error card — **Copy input** (stdin кейса в буфер).
2. Пользователь правит решение в редакторе.
3. Возврат в оболочку → **Run again** (тот же путь/режим/кейс) —
   не перевбивая путь. Строка обновляется на месте.

### J6. Микро-бенчмарк (режим 4)

1. В command bar — сегмент **Микро-бенчмарк**, путь к папке с ≥1 решением,
   профиль calls-per-run (fast/normal/…), ▶.
2. Result panel: таблица микробенча — метрики в **µs**
   (`Min/Median/Mean/Max/Std dev`), `Relative`, `Verdict`
   (`SIMILAR`/`SLOWER`/`MUCH SLOWER`) и колонка **`Py-heap`** (не `Memory`).
3. Клик по строке → detail panel с разбором (design-only, см.
   [web-design.md](web-design.md#per-block-detail-разбор-микробенча)).

### J7. Пробел в глоссарии → очередь пополнения

1. Решение падает с RE/WA на конструкции, для которой **нет карточки** в
   локальной базе (напр. незнакомое исключение или функция).
2. `MissingConceptDetector` фиксирует пробел → карточка **`GlossaryMissingEntry`**
   со статусом `new` попадает в очередь пополнения (раздел «Глоссарий» →
   «Недостающее»/backlog).
3. error card показывает бейдж «нет карточки — добавлено в очередь» вместо
   мёртвой ссылки.
4. Позже карточка наполняется (`draft` → `ready`) и может быть
   экспортирована во внешний Glossary-Python (экспорт — design-only).

## Модель error cards (WA/RE/TLE)

Единая карточка ошибки для трёх вердиктов. Строится на бэкенде из результата
`run_single_test` (уже содержит `verdict`, `error`, `diff`, `time`) плюс
lookup по глоссарию (`web/viewmodels.py::_case_view`).

| Поле | Тип | WA | RE | TLE | Описание |
|---|---|:--:|:--:|:--:|---|
| `verdict` | `"WA"\|"RE"\|"TLE"` | ✓ | ✓ | ✓ | Вердикт кейса |
| `severity` | `"error"\|"warning"\|"info"` | error | error | warning | Для цвета/иконки |
| `case_n` | `int` | ✓ | ✓ | ✓ | Номер тест-кейса |
| `stdin` | `string` | ✓ | ✓ | ✓ | Вход кейса (для Copy input) |
| `expected` | `string` | ✓ | — | — | Ожидаемый вывод |
| `actual` | `string` | ✓ | ± | ± | Фактический stdout |
| `diff` | `string` | ✓ | — | — | Готовый diff (как в CLI verbose) |
| `stderr` | `string` | — | ✓ | ± | Трейсбек / диагностика |
| `exit_code` | `int \| null` | — | ✓ | ± | Код возврата процесса |
| `timeout_s` | `float \| null` | — | — | ✓ | Лимит, который был превышен |
| `time` | `float` | ✓ | ✓ | ✓ | Затраченное время (с) |
| `suggestions` | `string[]` | ± | ✓ | ✓ | Короткие подсказки |
| `glossary_ids` | `string[]` | — | ✓ | ± | Якоря карточек (`recursionerror`, …) |
| `actions` | `CommandAction[]` | ✓ | ✓ | ✓ | Доступные action cards (см. ниже) |

- **Severity** управляет только представлением (цвет рамки/бейджа), не
  логикой. TLE — `warning` (это не крэш кода, а превышение лимита), WA/RE —
  `error`.
- **`glossary_ids`** заполняется из `lookup_from_error()` (RE — по типу
  исключения). Пусто → блок глоссария в карточке не рисуется.
- **`suggestions`** — курируемые односрочники (не AI): для TLE — про
  сложность; для RE — hint из `core/glossary.py`; для WA — «сравните
  хвостовые пробелы/перевод строки» при подозрении на форматирование.

Пример (RE):

```json
{
  "verdict": "RE",
  "severity": "error",
  "case_n": 3,
  "stdin": "1000000\n",
  "actual": "",
  "stderr": "Traceback (most recent call last):\n  ...\nRecursionError: maximum recursion depth exceeded",
  "exit_code": 1,
  "time": 0.42,
  "suggestions": ["Похоже на бесконечную/глубокую рекурсию — проверьте базовый случай."],
  "glossary_ids": ["recursionerror"],
  "actions": ["run_again", "copy_input", "explain_error", "open_glossary"]
}
```

## Action cards

Контекстные действия, привязанные к результату/кейсу. Карточка/кейс сам
объявляет доступные действия (`actions: []`), а UI рендерит только их.

| Действие | `id` | Контекст | Что делает |
|---|---|---|---|
| Run again | `run_again` | любой результат/кейс | Повторить прогон с тем же путём/режимом/кейсом |
| Copy input | `copy_input` | кейс с `stdin` | Копирует stdin кейса в буфер |
| Copy output | `copy_output` | кейс с `actual`/`expected` | Копирует фактический (или ожидаемый) вывод |
| Explain error | `explain_error` | WA/RE/TLE | Разворачивает `suggestions` + hint inline |
| Open glossary | `open_glossary` | есть `glossary_ids` | Deep-link в раздел «Глоссарий» на карточку |

Это MVP-набор — реализован целиком, чистый фронтенд поверх уже
возвращаемых данных. `create_test`/`compare_solutions` остаются design-only,
см. [web-design.md § Action cards, отложенные](web-design.md#action-cards-отложенные).

Каждое действие — **декларативное** (`CommandAction`, см. контракты), а не
захардкоженная кнопка. Одно и то же действие доступно и как action card в
detail panel, и как команда в palette.

## Command palette (Ctrl+K)

Единая точка запуска команд — как в VS Code. `Ctrl+K` (или `⌘K`) открывает
поиск (substring, не fuzzy — см. ниже) по **реестру команд** (реализован в
`src/stepik_grader/web/commands.py`).

```
┌── ⌘K ────────────────────────────────────┐
│ > run again                                │
├────────────────────────────────────────────┤
│ ▶ Повторить проверку              Run again │
│ ⧉ Скопировать вход              Copy input  │
│ 📖 Открыть глоссарий          Open glossary │
│ 🌙 Переключить тему             Toggle theme│
│ ↔ Переключить раздел            Проверка⇄Гл.│
└────────────────────────────────────────────┘
```

**Command registry model** — единый реестр, который питает и palette, и
action cards:

```jsonc
// CommandAction
{
  "id": "open_glossary",          // стабильный идентификатор
  "title": "Открыть глоссарий",   // подпись (i18n: ru/en, как cli._MESSAGES)
  "icon": "book",                  // имя иконки (опц.)
  "keywords": ["glossary","help"], // для substring-поиска
  "when": ["glossary_ids"],        // фикс. словарь тегов контекста (не строка-предикат)
  "shortcut": "g",                 // опц. хоткей внутри контекста
  "payload_schema": "GlossaryRef"  // тип аргумента (см. контракты)
}
```

- **Расширяемость.** Новая команда = новая запись в реестре + один обработчик;
  UI (palette/cards) не трогается.
- **i18n.** `title`/описания — по той же схеме, что `cli._MESSAGES` (ключ →
  `{ru, en}`), чтобы не расходиться с CLI (issue #51 D-01).
- **Реализовано (issue #125).** Палитра с фиксированным набором
  (run/copy/glossary/theme/section), `when` — фиксированный словарь тегов
  контекста (не predicate-DSL, как в изначальном дизайне — сознательное
  упрощение при реализации), поиск — substring (не fuzzy). Внешние плагины
  команд остаются design-only, см.
  [web-design.md § Command palette, отложенное](web-design.md#command-palette-отложенное).

## Архитектура web UI

Эволюция без переписывания ядра. Три слоя, граница между ними — стабильный
API-контракт (см. [контракты](#контракты-данных) и [api.md](api.md)).

```
┌── Frontend (SPA/vanilla JS) ────────────────┐
│   разделы, split-pane, palette, cards       │
└───────────────▲─────────────────────────────┘
                │  HTTP JSON API — см. api.md
┌───────────────┴─────────────────────────────┐
│  Web API / Adapters (src/stepik_grader/web/) │
│   viewmodels.py, downloader_adapter.py,      │
│   glossary_adapter.py, commands.py, runs.py  │
└───────────────▲─────────────────────────────┘
                │  вызовы публичных функций (как CLI)
┌───────────────┴─────────────────────────────┐
│  Core (библиотека, НЕ меняется)              │
│   grader_core, test_loader, glossary, …      │
└──────────────────────────────────────────────┘
```

**Инварианты архитектуры:**

1. **Core остаётся библиотекой.** Web-слой — потребитель `run_tests`,
   `run_benchmark`, `lookup_from_error`, как и `cli.py`. Никакой web-специфики
   в `core/` (DAG без циклов сохраняется, `web → core` — существующее ребро,
   см. [architecture.md](architecture.md)).
2. **UI не связан с внутренностями CLI.** Фронтенд общается только с HTTP
   API, не импортирует `cli.py` и не парсит его вывод. Adapters-слой —
   единственное место, где core-`dict` превращается в
   `ResultViewModel`/`ErrorCard`. CLI и Web — два независимых адаптера над
   одним ядром.
3. **Контракт — граница.** Меняя core, обновляем мэппер в adapters, а не
   фронтенд.
4. **Прогрессивность.** Остаётся на stdlib `http.server` + vanilla JS —
   переход на выделенный бэкенд (FastAPI и т.п.) или полноценный SPA-фреймворк
   не требуется. Любая тяжёлая зависимость — только по явному решению (см.
   запрет в `CLAUDE.md` на новые зависимости без указания).

**Реализованные адаптеры:**

- **Downloader-адаптер** (#186) — `web/downloader_adapter.py`, тонкая
  web-обёртка над `downloader.py::process_step_url` +
  `core/oauth_flow.try_create_session_without_browser`. Отдаёт
  `DownloadedTask`. Ребро DAG: `web → downloader → core` (ациклично).
- **Glossary provider/store** (#126) — локальная база карточек
  (JSON→SQLite), расширяет `core/glossary.py`. Отдаёт `GlossaryCard`.
  Реализован в `stepik_grader.glossary` — см. [glossary.md](glossary.md).
- **`MissingConceptDetector`** (#126) — анализ решений/ошибок →
  `GlossaryMissingEntry` в очередь пополнения.
- **`runs.py`** (#262) — async job-модель для bench/microbench
  (`POST /api/v1/runs`), альтернатива синхронному `GET /api/grade` — см.
  [api.md](api.md).

Экспорт/bridge во внешний Glossary-Python остаётся design-only, см.
[web-design.md](web-design.md#экспортсинхронизация-глоссария-во-внешний-проект).

**Полный справочник эндпоинтов** (методы, параметры, лимиты, коды ответов,
curl-примеры) — [api.md](api.md), не здесь.

## Контракты данных

Псевдо-схемы (Markdown/JSONC). Имена — типы adapters-слоя.

### ResultViewModel

Возврат `GET /api/grade` (см. [api.md](api.md)). Строится
`grade_path()`/`grade_benchmark()`/`grade_microbench()`.

```jsonc
// ResultViewModel
{
  "kind": "file" | "dir" | "error",
  "mode": "tests" | "bench" | "microbench",
  "base": "путь-база для относительных имён",
  "rows": [ SolutionRow ],       // по одному решению
  "message": "текст ошибки"       // только при kind=error
}

// SolutionRow (mode=tests)
{
  "file": "task1.py",
  "status": "OK" | "FAIL" | "NO TESTS",
  "passed": 5, "total": 5,
  "total_time": 0.12, "avg_time": 0.02, "memory_mb": 8.3,
  "cases": [ CaseView ]          // раскрытие
}

// CaseView → расширяется до ErrorCard при непрохождении
{
  "n": 3,
  "verdict": "AC" | "WA" | "RE" | "TLE",
  "time": 0.42,
  "error": "…",                  // stderr, если есть
  "diff": "…",                   // при WA
  "glossary": { "exception": "…", "hint": "…", "url": "…" } // issue #72
}
```

### ErrorCard

Надстройка над `CaseView` для WA/RE/TLE — поля из
[таблицы выше](#модель-error-cards-waretle). Строится adapters-мэппером из
`run_single_test` + `lookup_from_error`.

### CommandAction

Единая запись реестра команд (палитра + action cards) — см.
[Command palette](#command-palette-ctrlk). Поля: `id`, `title` (i18n),
`icon?`, `keywords[]`, `when`, `shortcut?`, `payload_schema?`.

### DownloaderRequest / DownloadedTask / TestCaseSet

Контракты блока [Downloader](#downloader--загрузка-тестов). Строятся
adapters-слоем над `downloader.py`.

```jsonc
// DownloaderRequest — аргумент POST /api/download
{
  "url": "https://stepik.org/lesson/569749/step/4?unit=564263",
  "root": "StepikTasks"           // корневая папка (опц., default из конфига)
}

// DownloadedTask — результат загрузки
{
  "ok": true,
  "path": "StepikTasks/курс/секция/урок/04-slug",  // куда положено (→ command bar)
  "files": ["task4_1.py", "task4_2.py", "task.md", "meta.json"],
  "tests": TestCaseSet,
  "message": "текст ошибки/предупреждения"  // при ok=false или ⚠️ (нет тестов)
}

// TestCaseSet — извлечённые тест-кейсы
{
  "count": 5,
  "source": "zip" | "html_table" | "github_link" | "none",  // 4 приоритета downloader.py
  "format": "legacy" | "named" | "python_generation"        // автодетект формата
}
```

### GlossaryMissingEntry

Элемент очереди пополнения (см.
[§ Глоссарий](#глоссарий-как-локальный-knowledge-модуль)). Пишется
`MissingConceptDetector` при обнаружении конструкции без карточки.

```jsonc
// GlossaryMissingEntry
{
  "concept": "functools.reduce",   // недостающая функция/конструкция/исключение
  "kind": "function" | "exception" | "construct",
  "status": "new" | "draft",       // жизненный цикл до появления GlossaryCard
  "seen_in": ["task3_1.py"],       // где встретилось (решение/ошибка)
  "verdict": "RE" | "WA" | null,   // вердикт, если пробел найден из ошибки
  "first_seen": "2026-07-06"
}
```

### GlossaryCard / GlossaryRef

Карточка **локальной базы** раздела «Глоссарий» (см.
[§ knowledge-модуль](#глоссарий-как-локальный-knowledge-модуль)). Компактный
источник — `core/glossary.py` (`GlossaryEntry`) для встроенных исключений;
расширенный контент и хранение — через `GlossaryProvider`/store (#126) в
локальной JSON/SQLite-базе проекта. `url` ведёт во внешний
[Glossary-Python](https://github.com/ArtVsMark/Glossary-Python) (куда карточка
экспортируется — экспорт design-only), но **истина хранится локально**.

```jsonc
// GlossaryRef — аргумент команды open_glossary
{ "id": "recursionerror" }       // = GlossaryEntry.anchor

// GlossaryCard
{
  "id": "recursionerror",        // якорь (slug), = GlossaryEntry.anchor
  "title": "RecursionError",
  "kind": "exception" | "function" | "construct" | "term",
  "hint": "однострочное пояснение (RU)",   // из core/glossary.py
  "body": "расширенное описание",           // из локального store (#126), опц.
  "status": "draft" | "ready" | "exported", // жизненный цикл карточки
  "url": "https://artvsmark.github.io/Glossary-Python/#recursionerror",
  "section": "Исключения",
  "related": ["stackoverflow", "maximum-recursion-depth"]
}
```

> `id`/`url` уже выводимы из `core/glossary.py` (`GlossaryEntry.anchor` /
> `.url`, `GLOSSARY_BASE_URL`). `kind`/`body`/`section`/`related`/`status` —
> расширение локального store (#126). `status` связывает карточку с очередью
> пополнения (`GlossaryMissingEntry`) и экспортом.

## Доступность, клавиатура, тёмная тема

- **Тёмная тема.** Через `prefers-color-scheme` (CSS-переменные), плюс явный
  тумблер (topbar) с сохранением выбора (localStorage), дефолт «системная».
- **Клавиатура.**
  - `Ctrl+K` / `⌘K` — command palette.
  - `Enter` в поле пути — запуск.
  - `Tab`-навигация по интерактивным элементам; видимый focus-ring.
  - Внутри palette — `↑`/`↓` выбор, `Enter` запуск, `Esc` закрыть.
  - Хоткеи действий из реестра (`CommandAction.shortcut`) активны только в
    их контексте (`when`).
- **Доступность (a11y) — базовый уровень реализован.**
  - Семантическая разметка: таблицы результатов — настоящие `<table>` с
    `<th scope>`; вердикты дублируются текстом, не только цветом
    (`renderVerdict()` всегда вставляет строку вердикта в бейдж).
  - Панели/диалоги — с `role`/`aria-label`; палитра — `role="dialog"` с
    возвратом фокуса при закрытии.
  - **Объявление результатов (issue #298).** Скрытый polite live-region
    `#result-announce` (`aria-live="polite"`) озвучивает одну строку-сводку
    исхода по ЗАВЕРШЕНИИ прогона («task_1.py — OK, 12 из 12» / «Бенчмарк
    завершён: N решений» / текст ошибки/отмены) — не на каждый прогресс-тик,
    иначе был бы шум. После завершения фокус переводится на панель
    результатов (`#restab-table[tabindex="-1"]`).
  - **Прогресс-бар** долгого прогона — `role="progressbar"` +
    `aria-valuemin/valuemax/valuenow` (неопределённый — `aria-valuetext`).
  - Контраст бейджей/вердиктов ≥ WCAG AA 4.5:1 в обеих темах: токен
    `--color-warning` в тёмной теме поднят до `#d98a5c` (issue #298 — прежний
    `#bb653b` давал ~3.5–4.4:1 для SLOWER на тёмных surface).

Полный a11y-аудит остаётся design-only, см.
[web-design.md § Полный a11y-аудит](web-design.md#полный-a11y-аудит).

## Безопасность и локальное исполнение

- **Только localhost.** Сервер слушает `127.0.0.1` и в сеть не торчит.
- **OS-sandbox для веб-запуска — opt-in.** По умолчанию решения исполняются в
  subprocess **без** изоляции ФС/сети — тот же threat model, что у CLI без
  `--sandbox`. С `--serve --sandbox` (issue #396) `SandboxRunner` (issue #266)
  ставится активным runner'ом до старта, и grade/playground/microbench
  изолируются разом; пошаговый трейс под `--sandbox` недоступен. Есть таймаут
  (всегда) и best-effort лимит памяти на POSIX. Без `--sandbox` запускай только
  доверенные решения (свои / скачанные из Stepik as-is).
- **XSS в выводе.** Веб-оболочка показывает stdout/stderr решения — весь
  такой контент экранируется при рендере (`esc` на клиенте, `html.escape` на
  сервере) — правило действует и на новые поля error card (`stdin`,
  `actual`, `stderr`, `diff`).
- Подробная threat model и настройки лимитов —
  [configuration.md § Ограничения и безопасность](configuration.md#ограничения-и-безопасность),
  [api.md § Общие правила](api.md#общие-правила-для-всех-api).
  Полноценный multi-tenant sandbox — вне рамок этого документа, см.
  [server-mode.md](server-mode.md) и запрет в
  [`CLAUDE.md`](../CLAUDE.md): «НЕ запускать executor.py с untrusted-кодом».
