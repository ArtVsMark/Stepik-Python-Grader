Параллельные сохранения решений больше не затирают друг друга. Сервер многопоточный, а новый файл заводился в два шага — «узнать свободное имя», затем «записать», — и между ними успевал вклиниться соседний запрос. Восемь одновременных сохранений давали восемь ответов «сохранено», четыре файла на диске и четыре молча потерянных решения. Теперь имя занимается тем же вызовом, что и создание файла (issue #922, находка `RUN-3-02`).
