# Документация Stepik Python Grader

Четыре направления — заходи в то, которое про тебя. Обзор проекта и быстрый
старт — в корневом [README](../README.md).

| Направление | Для кого | Что внутри |
|---|---|---|
| **[use/](use/README.md)** — как пользоваться | ученик, любой пользователь | установка и OAuth, режимы 1–4 и CLI-флаги, веб-интерфейс, конфигурация, форматы тест-кейсов |
| **[dev/](dev/README.md)** — как устроено | контрибьютор, разработчик | архитектура и дерево модулей, HTTP API, контракты данных, ADR, дизайн незапущенного server mode |
| **[agent/](agent/README.md)** — для Claude Code | агент и мейнтейнер | шаблон ролей, очередь работ после аудита |
| **[archive/](archive/README.md)** — что было | по необходимости | история разработки, архив CHANGELOG, разовые аудиты, завершённые планы |

Плюс два файла рядом с кодом: [`../CHANGELOG.md`](../CHANGELOG.md) — что
изменилось в каждом релизе, [`../CONTRIBUTING.md`](../CONTRIBUTING.md) — как
внести вклад. Политика безопасности — [`../SECURITY.md`](../SECURITY.md),
инварианты для агентов — [`../CLAUDE.md`](../CLAUDE.md).

## Два правила, на которых держится эта документация

**Одна тема — один файл.** Каждая тема живёт ровно в одном каноническом
документе, остальные на него **ссылаются**, а не копируют. Правишь тему —
правишь только её файл. Канонические источники перечислены в индексе каждого
направления.

**В активном документе нет журнала работ.** `use/` и `dev/` отвечают на «как
это работает **сейчас**». Что и в каком порядке было сделано — в
[`../CHANGELOG.md`](../CHANGELOG.md) и [`archive/`](archive/README.md); что
предстоит — в GitHub Issues (`gh issue list`). Номер issue в тексте уместен
только там, где объясняет неочевидный компромисс, — а не хвостом в каждой
строке.

> **Числа не хардкодятся.** Тесты, покрытие и размер глоссария живут только в
> бейджах README, версия — в git-тегах. Любая цифра, вписанная в прозу,
> устаревает к следующему PR и начинает противоречить соседнему файлу.
