**Рекомендации.**
1. Починить №1 немедленно (однострочно: `strict=False` + zip по фактически прогнанным кейсам, либо срез `test_cases[:len(res["cases"])]`) и добавить тест «cancel во время tests-job» — единственный подтверждённый функциональный баг, доступный из UI одной кнопкой.
2. В `gradeAsync` проверять форму ответа (`data.progress` может отсутствовать) и любой не-2xx/не-job ответ завершать цикл с сообщением — плюс общий helper для двух почти одинаковых poll-циклов (`gradeAsync`/`submitSandboxRun`).
3. Спланировать распил app.js на ES-модули (`grade.js`, `sandbox.js`, `trace-player.js`, `glossary.js`, `ui.js`); для этого — генерировать `_STATIC_ROUTES` сканом `static/` на импорте (по-прежнему без файлового сервера и traversal-поверхности).
4. В `RunOutcome` при TLE отдавать частично сдренированный вывод (в polling-ветке он уже в памяти) — заметное улучшение DX студента почти бесплатно.
5. При реализации server mode (#151) заложить лимит очереди jobs (HTTP 429) и вынести sync `/api/grade` (режим 2) на async-путь — сейчас deprecated-путь живёт параллельно и держит поток на весь прогон.

**Итог.** Ядро (executor/runner/grader_core) — зрелое, слоистое, с честными комментариями о компромиссах; web-слой функционально богат и хорошо задокументирован, но у async-джобов два реальных бага на пути отмены/восстановления, а фронтенд перерос формат одного файла. Оценка направления: **7.5/10**.
