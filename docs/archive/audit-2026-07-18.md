## Исполнительное резюме

Проект инженерно зрелый и стабильный: 1645 passed / 23 skipped, single-OS покрытие 89.21 % (порог 85), mypy/ruff чисто, критических (P0) уязвимостей нет, DAG без циклов, конкурентность subprocess-раннера и SQLite-истории проработаны образцово, а периметр localhost-сервиса (Host/Origin/Sec-Fetch-гарды, конфайнмент путей, SSRF-allowlist, OAuth-state, секреты 0600, редакция логов) выстроен грамотно.

**Главная проблема проекта — не инженерная, а разрыв «зрелость есть, а упаковки и вывода на витрину нет».** Три стратегических актива уже написаны в коде, но не доведены до пользователя:

1. **Глоссарий** — фактически **912 ready** карточек из 1362, но README/CHANGELOG/докстринги занижают на **311 карточек** в нарушение собственного правила CLAUDE.md #398.
2. **Retention-контур** (дашборд прогресса, TTFG, streak) полностью существует в `insights.py`/`progress_export.py`, но в web выведены только затухающие learning-карточки «Подучить».
3. **AI-репетитор** (`ai_hints.py`, BYOK, ADR-0003) заперт в CLI-режимах 1/2 и невидим в браузерном UX, где барьер входа ниже всего.

Параллельно остаются точечные дефекты верификации: реальная потеря данных студента при повторном скачивании (downloader безусловно затирает `task{N}_1.py`), незакрытый `EOFError` на вложенных prompt'ах, неатомарная запись очереди пополнения глоссария, недостоверный замер памяти под Linux-sandbox (RSS процесса-лаунчера `bwrap`), масочный тест fallback версии, нелокализованная UI-оболочка при контроле «Язык интерфейса», и пустая воронка контрибьюторов (0 good-first-issue при идеальном пуле — студентах курса).

**Правильная стратегия:** сначала дешёвый surfacing готового (глоссарий-счётчик, web-дашборд, AI в web) и растяжка воронки сообщества, затем средне-дорогие инфраструктурные консолидации (персистентность, граница web↔core, i18n), и только потом дорогой server mode, для которого сейчас блокер — процессно-глобальные синглтоны, а не «отложенность».

## 1. 🏛 Архитектор

Оба владельческих аудита **завышают** проблему границы: [B]§1 фактически неверен (glossary/rules уже несут по своему `runtime_checkable` Protocol), а sandbox-проброс в `--serve` (#396) и web-история `source="web"` (#395) уже реализованы. Настоящий архитектурный долг — процессно-глобальные синглтоны (`_RUNNER`, `_web_record_history`, `_JOBS`), прошивающие допущение «один сервер = один процесс = один пользователь», и хрупкие точки расширения раннеров.

| ID | Находка | Severity | Путь решения |
|---|---|---|---|

## Расхождения ролей и разрешение

**1. Общий ContentProvider Protocol для glossary/rules ([B]§1).**
Позиция [B]§1: «единственная абстракция — Runner Protocol; ввести общий Protocol». 🏛 Архитектор: премиса **фактически неверна** — оба подпакета уже несут `runtime_checkable` `GlossaryProvider`/`RulesProvider` с `get()`/`search()`.
→ **Разрешение:** оставить два раздельных Protocol (правило трёх). Общий ContentProvider — только при третьем типе контента, через generic-композицию. Исправить неверную премису в аудит-доках (E5/ADR-0010).

**2. web не проброшен через `--sandbox` и пишет историю слабее CLI ([A]/[B]§3).**
Позиция аудитов: открытые P1. Роли (🏛🔧📊🚀🎓🔐🧪): тезисы **устарели** и подтверждены кодом как сделанные — #396 (`set_runner(SandboxRunner())` до старта), #395 (`source='web'`, дефолт True), #430 (тумблер).
→ **Разрешение:** переклассифицировать из «реализовать» в «сделано — усилить видимостью». Реальный остаток: баннер статуса (E10) + onboarding-нудж (E2/T11).

**3. `run_single_test` >150-200 строк ([A]🔧).**
🔧 Разработчик (AST-замер): `run_single_test` = 56 строк; реальная длинная функция одна — `main()` в CLI (219 строк).
→ **Разрешение:** тезис отклонён по фактуре. Рефакторить `main()`, не `run_single_test`.

**4. JSON RMW «гонка при параллельных web-запросах» ([A]🔧).**
🔧🧪: внутрипроцессная гонка **уже закрыта** (`stats._WRITE_LOCK`, `_MISSING_QUEUE_LOCK`, #352, покрыто тестами); открыта только **межпроцессная** гонка CLI+`--serve`.
→ **Разрешение:** переформулировать риск как межпроцессный; закрывается миграцией missing-queue (E6).

**5. Состав SQL-унификации: тащить ли stats/cache в SQLite ([B]§2).**
🐍 Core Python Dev: `core/db.py` и миграция missing-queue — да; `stats.jsonl` **НЕ трогать** (append-only JSONL сознательно устойчив к обрыву); cache — low-priority; единый `.grader.db` для всего — **нет** (разный жизненный цикл).
→ **Разрешение:** приоритетно мигрировать missing-queue; stats оставить JSONL; cache опционально с прунингом; общий модуль подключения — да, общий физический файл — нет.

**6. Приоритет #363: P0 (владелец) vs P1 (product/growth).**
📊/📣/🚀: с product-призмы #363 — P1 (вторичная справочная ценность); выше по эффекту/код — surfacing готового.
→ **Разрешение:** #363 — параллельный P1-контент-трек (E1), не блокирует surfacing. Порядок: авто-счётчик и web-дашборд/AI **впереди** добивания волн. #363 переосмыслен как community-актив.

**7. LLM SDK как opt-in extra ([A]🐍).**
🐍/📡: ADR-0003 сделал **сильнее** — SDK отвергнут целиком (голый requests), extra не нужен, инвариант 3 зависимостей сохранён.
→ **Разрешение:** зафиксировать инвариант — LLM только opt-in HTTP, никогда провайдерский SDK/runtime-зависимость.

**8. Linux-sandbox тесты «молча скипаются в CI» ([A]🧪).**
🧪: **устарело** — #420 добавил privileged-джоб с hard-fail тестом; реальная дыра — асимметрия: такого guard'а нет для macOS/Windows.
