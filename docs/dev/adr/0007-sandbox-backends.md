# ADR-0007 — OS-уровневая песочница: opt-in, три backend'а по ОС

- **Статус:** Accepted (ретро-запись уже реализованного решения — `SandboxRunner`
  внедрён в issue #266 по требованиям дизайна #157; ADR фиксирует его задним
  числом, D3 аудита)
- **Дата:** 2026-07-16
- **Связанные issue:** #157 (требования sandbox, дизайн), #266 (реализация
  `SandboxRunner`), #396 (web `--serve --sandbox`), #417 (микробенч под sandbox),
  #420 (Linux `bwrap` в CI)
- **Связанный код/доки:** [core/sandbox/](../../../src/stepik_grader/core/sandbox/)
  (`SandboxRunner`, `_linux`/`_macos`/`_windows`), [SECURITY.md](../../../SECURITY.md)
  (канон таблицы гарантий), [docs/server-mode.md § Sandbox и сетевая изоляция](../design/server-mode.md);
  реализует [ADR-0001](0001-server-mode.md), backend поверх [ADR-0006](0006-runner-abstraction.md)

## Контекст

По умолчанию грейдер исполняет **доверенный** код (свой или скачанный из Stepik
as-is) в subprocess **без OS-sandbox** — осознанное by-design ограничение
(CLAUDE.md инвариант 4, [SECURITY.md](../../../SECURITY.md)).

[ADR-0001](0001-server-mode.md) сделал реальную изоляцию **предусловием** любого
исполнения недоверенного кода (фаза 2 на пути к server mode). Issue #157
зафиксировал **требования** к sandbox (сеть off, эфемерные tmp-каталоги, жёсткие
квоты, изоляция клиентов), но **сознательно не выбирал механизм**. Нужен
конкретный, кроссплатформенный, обратимый механизм, который не ломает дефолтный
локальный путь и не тянет тяжёлых зависимостей/демонов (запреты CLAUDE.md).

## Решение

1. **`SandboxRunner` реализует протокол `Runner`** ([ADR-0006](0006-runner-abstraction.md)) —
   тот же контракт `run(RunSpec) -> RunOutcome`, просто другой backend;
   `grader_core` не знает, какой активен (инъекция через `set_runner()`).
2. **Sandbox — opt-in (`--sandbox`), НЕ дефолт.** Без флага работает прежний
   `LocalRunner`. Доверенный локальный путь остаётся без изменений.
3. **Три backend'а, по одному на ОС, с РАЗНЫМИ гарантиями** (полная таблица —
   [SECURITY.md](../../../SECURITY.md), здесь не дублируется):
   - **Linux** (`_linux.py`) — **bubblewrap**: сеть/ФС/CPU/процессы изолированы
     ядром (namespaces + `RLIMIT_*`), плюс `RLIMIT_AS` как backstop памяти.
   - **macOS** (`_macos.py`) — **`sandbox-exec`**: сеть/запись-в-ФС/CPU
     изолированы; чтение файлов сознательно НЕ ограничено; anti-fork-bomb слабее.
   - **Windows** (`_windows.py`) — **Job Objects**: память/CPU/процессы ядром,
     БЕЗ сетевой изоляции и без строгой ФС-изоляции (только cwd-контейнмент).
   Пробелы задокументированы, а не тихо пропущены.
4. **Fail-fast и fail-loud.** Backend выбирается при конструировании (ошибка на
   старте CLI, а не посреди прогона). Недоступен (`bwrap`/`sandbox-exec`/Job
   Objects нет) → `SandboxUnavailableError` с понятной причиной — **никогда**
   тихий fallback на `LocalRunner` (#266, явное требование).
5. **Только нативные ОС-примитивы.** Механизм не поднимает Docker/VM/демонов —
   в духе запретов CLAUDE.md и в отличие от отложенного `nsjail`-fallback.

## Альтернативы

- **A. Всегда-включённый sandbox (default-on).** Минус: ломает дефолтный
  доверенный локальный путь, платформо-зависимые провалы у обычных учеников,
  лишние ограничения там, где угрозы нет. Отклонено.
- **B. Docker / nsjail / VM.** Минус: тяжёлые зависимости и демоны против
  CLAUDE.md; неудобно ученику; `nsjail` рассматривался как Linux-fallback без
  `bwrap` (#266), но не реализован. Отклонено как механизм по умолчанию.
- **C. Один backend (только Linux).** Минус: macOS/Windows — основные десктопы
  аудитории — остаются без изоляции. Отклонено.
- **D. Три нативных backend'а, opt-in, fail-loud (выбрано).** Изоляция на всех
  трёх ОС без тяжёлых зависимостей, дефолт не тронут, гарантии честные и
  задокументированные.

## Последствия

**Положительные:**

- Изоляция доступна на всех трёх ОС без Docker/VM; дефолтное поведение не
  меняется (opt-in).
- Гарантии per-OS честные и задокументированы (SECURITY.md) — не создают ложного
  чувства безопасности.
- Готов фундамент фазы 2 server mode ([ADR-0001](0001-server-mode.md)): недоверенное
  исполнение имеет реальный механизм изоляции.

**Отрицательные / издержки:**

- Гарантии **не единообразны** по ОС (цена нативных примитивов): macOS не
  ограничивает чтение ФС, Windows — сеть. Это задокументированный, а не скрытый
  компромисс.
- Поддержка трёх платформенных backend'ов; на части окружений backend
  недоступен → `--sandbox` падает (fail-loud — осознанно).

**Нейтральные:**

- Sandbox — предусловие server mode, но сам по себе сеть/сервер не открывает:
  публичный server mode остаётся отдельным сдвигом (фаза 4, ADR-0001).
