# Как устроено

Для тех, кто правит код. Как **пользоваться** грейдером — в
[`../use/`](../use/README.md); правила вклада, код-стайл и версионирование — в
[`../../CONTRIBUTING.md`](../../CONTRIBUTING.md).

## Почему так решено

| Документ | О чём |
|---|---|
| [adr/README.md](adr/README.md) | **11 архитектурных решений по всему проекту** — контекст, решение, альтернативы, последствия: src-layout, динамическая версия, протокол `Runner`, OS-песочница, AI-интеграция, граница web↔core, локальная персистентность, серверные решения |

ADR отвечают на «**почему** так», документы ниже — на «**как** это работает».
Одно не дублирует другое.

## Контракты и форматы

| Документ | О чём |
|---|---|
| [api.md](api.md) | Справочник HTTP API `--serve`: все эндпоинты, параметры, лимиты, коды ответов, curl-примеры. Защищён контрактным тестом `test_web_api_contract.py` |
| [result-contract.md](result-contract.md) | Контракт результата проверки для CLI/Web/API: поля case/solution/run, семантика вердиктов, стабильность |

| [rules-insights.md](rules-insights.md) | Правила PEP 8 и учебные инсайты: формат `RuleCard`, `core/lint.py`, таксономия падений и затухание карточек |

## Веб-слой

| Документ | О чём |

| [web-contracts.md](web-contracts.md) | Контракт веб-слоя: user journeys J0–J7 (из них собраны e2e-тесты), модель error/action cards, реестр команд, устройство фронтенда, формы данных (`ResultViewModel`, `ErrorCard`, `GlossaryCard`, …) |
