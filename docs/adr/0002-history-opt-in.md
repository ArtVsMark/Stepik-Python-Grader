# ADR-0002 — Запись истории прогонов: opt-in по умолчанию (CLI)

- **Статус:** Accepted
- **Дата:** 2026-07-15
- **Связанные issue:** #430 (этот ADR, тумблер истории в меню), #344
  (`record_history`/SQLite), #134 (дефолт `False`), #395 (web-канал)
- **Связанный код:** [config.py](../../src/stepik_grader/config.py)
  (`GraderConfig.record_history`),
  [core/user_settings.py](../../src/stepik_grader/core/user_settings.py),
  [cli/interactive.py](../../src/stepik_grader/cli/interactive.py)

## Контекст

Флагманская фича «Подучить» (карточки частых ошибок, эпик #342) питается
локальной SQLite-историей прогонов (`.grader_history.db`, issue #344). Запись
истории — `GraderConfig.record_history`, дефолт `False` (issue #134): включается
CLI-флагом `--history`/`--no-history` или полем в `pyproject.toml`.

Issue #430 добавляет тумблер истории прямо в интерактивное меню (pipx-ученик не
редактирует `pyproject.toml`) и требует **зафиксировать ADR-заметкой**, остаётся
ли запись **opt-in** (выключена по умолчанию) или становится **default-on**
(включена, с возможностью отказа). Решение меняет поведение для всей аудитории и
касается приватности, поэтому его нельзя оставлять неявным.

Ключевые факты threat/privacy model:

- История пишется **только локально**, без сети (как `.grader_stats.jsonl`), но
  содержит имена задач, хеши решений и тайминги — это персональные данные учебной
  активности.
- Web-канал (`--serve`, issue #395) уже включает историю **по умолчанию** для
  браузерной аудитории: там БД очевидно-локальна, а раздел «Подучить» — часть UI,
  которую пользователь видит и осознаёт.
- CLI-запуск (`--mode`, меню) — более «тихий»: пользователь может не подозревать,
  что на диск пишется база с его активностью.

## Решение

1. **CLI-запись истории остаётся opt-in** — `GraderConfig.record_history`
   по-прежнему `False` по умолчанию. Ни `--mode`, ни интерактивное меню не
   начинают писать историю без явного согласия пользователя.
2. **Согласие даётся видимым действием:** флаг `--history`, поле
   `[tool.stepik-grader] record_history`, либо новый **тумблер в меню** (пункт 7),
   который сохраняется между запусками в `.grader_settings.json`
   (`core/user_settings.py`).
3. **Приоритет источников в меню:** user-state (`.grader_settings.json`) →
   `pyproject.toml` (`CONFIG.record_history`) → дефолт `False`. CLI-флаг
   `--history` остаётся высшим приоритетом в `--mode`-пути (меню через argparse
   не проходит).
4. **Мягкий nudge вместо тихого включения:** после прогона с падениями (режимы
   1/2) при выключенной истории печатается однократная подсказка, предлагающая
   включить запись (пункт 7 меню). Подсказка **не** меняет настройку сама.
5. **Web остаётся default-on** (issue #395) — это отдельный, осознанный контекст
   (см. Контекст); данный ADR фиксирует именно CLI-политику.

## Альтернативы

- **A. Default-on (opt-out) для CLI.** Плюс: «Подучить» наполняется без действий
  пользователя, воронка обучения работает сразу. Минус: меняет поведение для 100%
  существующей аудитории; тихая запись персональной активности на диск без явного
  согласия — против принципа наименьшего сюрприза и приватности; противоречит
  сознательно выбранному дефолту `False` (#134). Отклонено.
- **B. Opt-in + удобный тумблер и nudge (выбрано).** Плюс: сохраняет приватный
  дефолт и обратную совместимость; даёт лёгкий путь включения из продукта (меню),
  не редактируя конфиг; подсказка повышает discoverability без принуждения.
  Минус: пользователь должен сделать один явный шаг. Принято как баланс приватности
  и удобства.
- **C. Спрашивать при первом запуске (интерактивный prompt «включить историю?»).**
  Плюс: явный осознанный выбор. Минус: лишний трения на старте, ломает
  скрипты/CI, усложняет тесты. Отклонено в пользу ненавязчивого тумблера + nudge.

## Последствия

**Положительные:**

- Приватный дефолт сохранён; никакой тихой записи активности без согласия.
- Обратная совместимость: поведение существующих `--mode`/`--history`/pyproject
  не меняется.
- Появляется продуктовый путь включения (меню + персистентность), доступный
  pipx-ученику без правки `pyproject.toml`.

**Отрицательные / издержки:**

- Вводится новый слой персистентности user-state (`core/user_settings.py`,
  `.grader_settings.json`) — небольшой оверхед; митигируется тем, что это leaf-модуль
  на stdlib без зависимостей.
- «Подучить» в CLI не наполняется, пока пользователь не включит историю
  (осознанно — цена приватного дефолта).

**Нейтральные:**

- Асимметрия CLI (opt-in) vs web (default-on, #395) сохраняется намеренно и
  задокументирована здесь и в коде.
