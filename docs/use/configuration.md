## Где что настраивается

| Что | Где | Формат |
|---|---|---|
| Параметры грейдинга (таймауты, память, пороги, кэш) | `pyproject.toml` → `[tool.stepik-grader]` | TOML, читается в `GraderConfig`/`CONFIG` |
| Корневая папка задач и путь к `secrets.json` | `stepik_config.json` (в текущей папке) | JSON, пишется `downloader.py` |
| OAuth-токены Stepik | `secrets.json` | JSON, пишется `storage.save_secrets()` (см. [installation.md](installation.md#работа-с-api-stepik-oauth)) |
| Кэш результатов проверки | `.grader_cache/results.json` (в CWD) | JSON, opt-in (`--cache`) |
| Поведение pytest-плагина | `pyproject.toml` → `[tool.pytest.ini_options]` `grader_mode` | TOML |
| Хост Stepik API (тестовый стенд) | переменная окружения `STEPIK_GRADER_API_HOST` | URL со схемой, напр. `https://stage.example`; по умолчанию `https://stepik.org` |

## `[tool.stepik-grader]` в `pyproject.toml`

Единая точка правды для параметров грейдинга — dataclass `GraderConfig`
(`frozen=True`, потокобезопасно) в `src/stepik_grader/config.py`. `CONFIG`
вычисляется лениво при первом обращении (module `__getattr__`) —
`load_config()` читает секцию `[tool.stepik-grader]` из `pyproject.toml` и
кэширует результат; голый `import stepik_grader.config` диск не трогает.
Если файла или секции нет — используются дефолты.

**Значения проверяются при загрузке.** Каждое поле имеет правило (тип и
допустимый диапазон): `timeout_seconds` — число больше 0, `job_workers` и
прочие счётчики — целое не меньше 1, `encoding` — имя кодека, известного
Python, флаги — только `true`/`false`. Неподходящее значение не роняет
грейдер: ключ отбрасывается, подставляется дефолт, а в stderr печатается
предупреждение с именем параметра, допустимым диапазоном и подставленным
значением. Незнакомое имя ключа тоже не игнорируется молча — о нём
предупреждают отдельно, потому что опечатка в имени неотличима от «параметр
настроен» (`timeout_second = 5` не применится никогда).

Прямое конструирование `GraderConfig(...)` из кода строже: негодное значение
поднимает `ValueError` с перечислением всех проблемных полей сразу — тихо
получить конфиг, который упадёт позже в раннере, нельзя.

**Порядок разрешения пути к `pyproject.toml`** (при установке
через pipx/wheel путь относительно расположения пакета указывал внутрь
окружения, и `[tool.stepik-grader]` молча никогда не читался):

1. Флаг `--config PATH` — явный файл конфигурации (высший приоритет).
   Несуществующий путь — ошибка разбора аргументов, а не тихий откат на
   автопоиск: раз файл назван, прогон должен идти именно с ним.
2. Переменная окружения `STEPIK_GRADER_CONFIG` — если указывает на
   существующий файл, используется он. Невалидное значение переменной не
   поднимает исключение — резолюция просто продолжается со следующего
   источника.
3. Поиск `pyproject.toml` от корня настроек вверх — **до границы проекта**
   и **только среди файлов с секцией `[tool.stepik-grader]`**. Границей
   служит каталог с `.git`, `.hg` или `.grader_settings.json`, а также
   домашний каталог пользователя. Чужой `pyproject.toml` (соседний проект,
   монорепозиторий, домашняя папка) в резолюции не участвует.
4. Legacy-fallback: путь относительно расположения самого пакета
   (`src/stepik_grader/config.py` → на два уровня выше) —
   применяется, только если предыдущие источники ничего не дали
   (сохраняет поведение при запуске тестов из корня репозитория).
5. Если ничего не найдено — дефолты `GraderConfig()`, без ошибок.

**Почему поиск ограничен.** Раньше подъём шёл до корня файловой системы и
брал первый попавшийся `pyproject.toml`: верное решение, дающее `AC` в своей
папке, получало `FAIL` по таймауту, если этажом выше лежал чужой файл с
другими параметрами прогона, — а синтаксическая ошибка в таком файле роняла
трейсбеком любую команду, включая `--help`. Теперь битый или недоступный
файл даёт предупреждение с путём и причиной, и грейдер продолжает работу.

**Корень настроек** — общий и для CLI, и для веба: от него резолвятся и
`pyproject.toml`, и `.grader_settings.json`. По умолчанию это ближайший вверх
от рабочей папки каталог с маркером проекта; `--serve --root PATH` задаёт его
явно. Прежде конфиг якорился на `cwd`, а веб-настройки — на `--root`, то есть
один запуск читал настройки из двух разных мест.

```toml
[tool.stepik-grader]
timeout_seconds = 10.0
similar_threshold = 1.15
much_slower_threshold = 1.50
measure_child_memory = true
microbench_max_cases = 5
```

**Полный список параметров:**

| Ключ | Тип | Дефолт | Назначение |
|---|---|---|---|
| `timeout_seconds` | `float` | `10.0` | Таймаут subprocess одного тест-кейса (режимы 1–3), защита от зависания. |
| `similar_threshold` | `float` | `1.15` | Порог вердикта `SIMILAR` в бенчмарке (относительно быстрейшего). |
| `much_slower_threshold` | `float` | `1.50` | Порог вердикта `MUCH SLOWER` в бенчмарке. |
| `measure_child_memory` | `bool` | `true` | `true` — мониторинг дочернего процесса через `psutil` (честнее, медленнее); `false` — RSS родителя (быстро, грубо). |
| `microbench_max_cases` | `int` | `5` | Максимум тест-кейсов при `timeit`-замерах (режим 4) для стабильного std-dev. |
| `encoding` | `str` | `"utf-8"` | Кодировка чтения файлов решений и тестов. |
| `max_memory_mb` | `int \| None` | `1024` | Best-effort лимит памяти дочернего процесса (POSIX-only, `RLIMIT_AS`); `None` — без лимита. См. [Ограничения и безопасность](#ограничения-и-безопасность). |
| `use_cache` | `bool` | `false` | Включить кэш результатов по умолчанию (эквивалент `--cache`). Отдельный запуск форсируется `--no-cache`. |
| `glossary_store` | `str \| None` | `None` | Путь к локальной JSON-базе карточек глоссария; `None` — веб-слой откатывается на компактный `core/glossary.py`. См. [glossary.md](../dev/glossary.md). |
| `glossary_missing_queue` | `str` | `".grader_glossary_missing.db"` | Путь к очереди пополнения глоссария (недостающие карточки): SQLite/WAL; legacy `.json`-очередь читается и разово импортируется при первой записи. См. [glossary.md](../dev/glossary.md). |
| `job_workers` | `int` | `2` | Размер пула воркеров async job-модели `--serve` (`POST /api/v1/runs`) — сколько bench/microbench-задач исполняются параллельно. Не CLI-флаг. |
| `record_stats` | `bool` | `false` | Включить локальную статистику запусков по умолчанию (эквивалент `--stats`). Отдельный запуск форсируется `--no-stats`. |
| `record_history` | `bool` | `false` | Писать историю прогонов в SQLite-базу `.grader_history.db` по умолчанию (эквивалент `--history`). Отдельный запуск форсируется `--no-history`. Основа разделов «Правила»/«Подучить». |
| `history_db_path` | `str` | `""` | Где лежит база истории обучения. Пусто — авторезолв: сначала существующая `.grader_history.db` рядом или выше по дереву (но не выше домашней папки), иначе единая `~/.stepik-grader/history.db`. Прежнее поведение «своя база в каждой папке» возвращается значением `".grader_history.db"` — относительный путь резолвится от текущей папки. |
| `insights_window_n` | `int` | `10` | Окно последних N прогонов для статуса карточек «Подучить» (`core/insights.py`) — по номерам прогонов, не по календарю. |
| `insights_active_threshold_t` | `int` | `2` | Порог активности T: ≥T попаданий ключа ошибки в окне N → карточка «активна». |
| `insights_clean_streak_k` | `int` | `3` | Чистая серия K: ≥K подряд чистых прогонов → карточка уходит в «архив побед». |
| `sandbox_max_cpu_seconds` | `float` | `10.0` | `--sandbox`: жёсткий лимит CPU-времени решения (backstop под общим `timeout_seconds`). |
| `sandbox_max_processes` | `int` | `32` | `--sandbox`: лимит числа процессов решения (anti-fork-bomb). На Linux под bwrap — абсолютное значение; на голом POSIX/macOS — бюджет сверх текущего числа процессов пользователя. См. [SECURITY.md](../../SECURITY.md). |
| `sandbox_max_output_bytes` | `int` | `10485760` (10 МБ) | `--sandbox`: лимит суммарного размера stdout+stderr решения. |
| `max_output_bytes` | `int` | `10485760` (10 МБ) | Потолок **накопления** stdout+stderr на обычном пути (без `--sandbox`). Вывод сверх лимита отбрасывается (в stderr добавляется пометка), чтение продолжается, процесс доживает до своего `timeout_seconds` — так ограничивается память хоста, а не время жизни решения. Действует на всех путях исполнения: грейдинг (CLI и web), песочница, пошаговый трейс, микробенчмарк. У трейса вывод программы дополнительно ограничен ещё и внутри дочернего процесса — см. [trace-format.md](../dev/trace-format.md). |
| `max_active_runs` | `int` | `20` | Back-pressure async job-модели `--serve` (`POST /api/v1/runs`): максимум одновременных нетерминальных job'ов; превышение → `429 too_many_runs`. Настройка сервера, не CLI-флаг и не параметр запроса. Фундамент server mode. |
| `ai_base_url` | `str \| None` | `None` | `--ai-hints` (ADR-0003): базовый URL OpenAI-совместимого эндпоинта (`{ai_base_url}/chat/completions`, на `requests`, без SDK). `None` — AI выключен (graceful skip). Работает и с облаком, и с локальным `ollama`. Схема проверяется: `https` — на любой хост, `http` — только на петлю (`localhost`/`127.0.0.1`/`[::1]`), иначе код решения и ключ ушли бы по сети открытым текстом. Согласие на отправку привязано к `scheme://host:port`: сменился получатель — спросят заново; отозвать — `--revoke-ai-consent`. |
| `ai_model` | `str \| None` | `None` | Имя модели для `--ai-hints`. Reasoning-семейства (o-серия OpenAI, имена с `thinking`/`reasoning`) распознаются по имени: им уходит `max_completion_tokens` и не уходит `temperature` — иначе провайдер отвергает весь запрос, и подсказки молча не работают. |
| `ai_api_key_env` | `str` | `"STEPIK_GRADER_AI_KEY"` | **Имя** env-переменной с API-ключом (не сам ключ). Значение ключа никогда не в конфиге/файлах — читается из окружения в момент вызова и редактируется в логах (`diag_log`). Локальному провайдеру (`ollama`) ключ не нужен. Допустимы только имена из своего пространства: дефолт или `STEPIK_GRADER_*` — иначе чужой `pyproject.toml`, приехавший вместе с папкой задач, мог бы назначить «ключом» посторонний секрет окружения (`GITHUB_TOKEN`) и отправить его вовне. |
| `ai_max_tokens` | `int` | `400` | Лимит токенов ответа AI-подсказки. |
| `ai_timeout_seconds` | `float` | `20.0` | Таймаут запроса к AI-эндпоинту; при истечении/сетевой ошибке — тихий пропуск, грейдинг не падает. |
| `ai_max_hints` | `int` | `5` | Потолок AI-подсказок за один прогон. Без него папка с 40 упавшими решениями давала 40 последовательных запросов по `ai_timeout_seconds` каждый — минуты ожидания и столько же оплаченных вызовов. Обрыв по потолку сообщается явной строкой. |
| `ai_grounding_k` | `int` | `3` | Сколько карточек глоссария кладётся в промпт как заземление. Порядок — по близости к падению: сначала карточка самого исключения из трейсбека, затем концепты, упомянутые в тексте ошибки, затем остальные в порядке кода. |
| `ai_system_prompt` | `str` | `""` | Свой системный промпт вместо встроенного. Встроенный обращается к новичку на курсе «Поколение Python» — задайте свой, если аудитория другая. Пусто — встроенный (и он выбирается по языку ответа; свой промпт один на оба). |

> **Приватность (`record_stats`/`--stats`).** Статистика —
> только локальный файл `.grader_stats.jsonl` в текущей директории (режимы,
> вердикты, ОС, суммарное время прогона). Никаких сетевых отправок — данные
> **не покидают машину** ни при каком значении этой настройки; проект в
> принципе не содержит кода, отправляющего телеметрию куда-либо. Файл — в
> `.gitignore`, не коммитить. Просмотр сводки — `stepik-grader --stats-summary`.

> **История прогонов (`record_history`/`--history`).** Тот же
> принцип приватности: локальная SQLite-база (прогоны, per-case
> вердикты/время/класс ошибки), только на машине, без сети. По умолчанию
> выключена — файл **не создаётся**, пока не задан `--history` или
> `record_history = true`. Основа разделов «Правила»/«Подучить»; построена на
> `sqlite3` из stdlib (WAL, миграции), best-effort — битая база не роняет
> проверку.
>
> **Где лежит база.** По умолчанию — одна на пользователя,
> `~/.stepik-grader/history.db`. Так «Подучить», «Прогресс», серия и бейджи
> наполняются независимо от того, из какой папки запущен грейдер: раньше база
> лежала строго в текущей папке, а рекомендованный сценарий — запуск из папки
> задачи, поэтому у каждой задачи заводилась своя история и разделы оставались
> пустыми.
>
> **Переход со старых баз.** Ничего делать не нужно: если рядом с рабочей
> папкой (или выше по дереву, но не выше домашней) уже лежит
> `.grader_history.db`, запись продолжится именно в неё — накопленное не
> осиротеет. Слить несколько старых баз в одну автоматически грейдер не умеет:
> перенесите нужную в `~/.stepik-grader/history.db` вручную либо укажите её
> через `history_db_path`. Прежнее поведение возвращается значением
> `history_db_path = ".grader_history.db"`.
>
> **Если база сломалась.** Проверка идёт как обычно, но в stderr один раз за
> запуск появляется путь к базе и причина: либо файл повреждён (удалите его —
> история заведётся заново, прежние прогоны не восстановить), либо база создана
> **более новой версией** грейдера (после отката поднимите версию обратно или
> удалите файл). Молчаливого «истории просто нет» в этих случаях больше нет:
> раньше повреждённая база выглядела как пустая, и прогоны уходили в никуда.
>
> **`.grader_stats.jsonl` vs `.grader_history.db`.** Это два
> независимых опциональных журнала, не дубликаты: `stats.jsonl` — плоская
> JSON-Lines сводка «режим/вердикты/ОС/время» на прогон (быстрый `--stats-summary`);
> `history.db` — структурированная per-case база для агрегатных выборок
> «Подучить»/«Правила», TTFG (`--insights`, `--export-progress`) и lint-истории.
> Метрики прогресса и инсайты читают **только** `history.db`; `stats.jsonl` оставлен
> как есть для обратной совместимости и лёгкой сводки.

> Значения из `pyproject.toml` перекрывают дефолты. `GraderConfig` — `frozen`:
> изменить его в рантайме нельзя (мутация → `FrozenInstanceError`). Полный
> список инвариантов ядра — в [`CLAUDE.md`](../../CLAUDE.md).

## `stepik_config.json` — корневая папка задач

При первом запуске `downloader.py` предложит указать корневую папку для задач и
путь к `secrets.json`:

```
Укажи корневую папку для всех задач Stepik [StepikTasks]:
Укажи путь к secrets.json [secrets.json]:
```

Значения сохраняются в `stepik_config.json` (в `.gitignore` — не коммитится).
Структура директорий внутри корневой папки:

```
StepikTasks/
└── <курс>/<секция>/<урок>/<NN>/ или <NN-шаг>/
```

Подробнее о том, как `downloader.py` раскладывает файлы задачи и ищет
тест-кейсы, — в [grader-workflow.md § Шаг скачивания задачи](grader-workflow.md#шаг-скачивания-задачи).

## `STEPIK_GRADER_API_HOST` — увести запросы со stepik.org

По умолчанию грейдер, загрузчик и диагностика ходят на `https://stepik.org`.
Переменная окружения `STEPIK_GRADER_API_HOST` переводит их все разом на другой
адрес — тестовый стенд, локальный макет API, зеркало:

```bash
STEPIK_GRADER_API_HOST=http://127.0.0.1:8000 python -m stepik_grader.downloader
```

Значение обязано начинаться с `http://` или `https://`. Опечатка без схемы не
принимается молча: грейдер пишет предупреждение в лог и остаётся на
`https://stepik.org` — иначе каждый запрос падал бы непонятной ошибкой
соединения.

Переменная не отменяет OAuth: `secrets.json` и токены нужны те же, и стенд
должен отвечать на `/oauth2/token/` и `/api/*` так же, как Stepik.

## Таймауты

### Таймаут subprocess (режимы 1–3)

Константа `TIMEOUT_SECONDS` в `core/grader_core.py` (значение из
`CONFIG.timeout_seconds`, по умолчанию `10.0` с) защищает от зависания решения —
передаётся в `timeout=` у `proc.communicate()`:

```python
TIMEOUT_SECONDS: float = 10.0  # секунд
```

### Microbench (режим 4)

Замер режима 4 обёрнут фиксированным `subprocess.run(timeout=60)` вокруг всего
цикла (5 повторов × N итераций). Локального per-call таймаута нет — см.
[Ограничения и безопасность](#ограничения-и-безопасность).

## Замер памяти дочернего процесса

```python
MEASURE_CHILD_MEMORY: bool = True  # False — быстрее, но грубее
```

- `True` (по умолчанию) — мониторинг дочернего процесса через `psutil` в
  отдельном потоке (честнее, но медленнее).
- `False` — RSS родительского процесса (быстро, приблизительно).

> Режим 4 (micro-bench) для stdin-блоков меряет пик **Python-heap через
> `tracemalloc`** (колонка `Py-heap`), а для function-блоков — RSS. `tracemalloc`
> не видит аллокации C-расширений (numpy и т.п.) — для чистого Python это
> приемлемо.

## Формат тест-кейсов

> **Единственный канонический источник по форматам тестов.** Остальные документы
> (README, grader-workflow.md, CONTRIBUTING.md) ссылаются сюда, а не дублируют.

Тест-кейсы лежат в папке `tests/` рядом с файлом(ами) решения:

```
module1/
└── task1/
    ├── task1_1.py        # основное решение
    ├── task1_2.py        # альтернативное решение 1
    └── tests/
        ├── 1             # входные данные теста №1 (stdin)
        ├── 1.clue        # ожидаемый вывод теста №1
        ├── 1.type        # тип теста: файл присутствует только для function-style задач,
        │                 # содержит строку "function"
        ├── 2
        ├── 2.clue
        └── ...
```

Файлы тестов читаются в кодировке UTF-8 (`CONFIG.encoding`).

**Вывод решения тоже должен быть корректным UTF-8.** Он декодируется строго, и
если решение печатает сырые байты, не образующие UTF-8, кейс получает `WA` с
явным указанием проблемного байта и его позиции. Терпимое декодирование здесь
недопустимо: любые непредставимые байты схлопывались бы в один и тот же символ
замены `�`, и разные выводы становились бы неотличимы — неверное решение
получало бы `AC`. Кириллица, эмодзи и любые другие не-ASCII символы — обычный
UTF-8 и под это правило не подпадают.

### Типы тестов (`*.type`)

| Значение в файле | Когда создаётся | Поведение |
|---|---|---|
| *(файл отсутствует)* | stdin-задача | входные данные подаются через `stdin` |
| `function` | function-style задача | входные данные — объявление переменной (`x = 5`), передаётся через `exec` |

### Три формата (автодетект)

Грейдер автоматически распознаёт три формата тест-кейсов:

| Формат | Файлы | Источник |
|---|---|---|
| **1 — Legacy** | `1`, `1.clue`, `2`, `2.clue` в `tests/` | Stepik ZIP / `downloader.py` (создаётся автоматически при скачивании) |
| **2 — Именованные** | `input_1.txt` + `expected_1.txt`, `input_2.txt` + `expected_2.txt`, … | ручное добавление |
| **3 — python-generation** (приоритет) | `tests/input.txt` + `tests/output.txt` с маркерами `# TEST_N:` | репозитории python-generation |

Format 3 используется репозиториями
[python-generation/Professional](https://github.com/python-generation/Professional),
[python-generation/OOP](https://github.com/python-generation/OOP),
[python-generation/Samurai](https://github.com/python-generation/Samurai). Stepik
ZIP-архивы автоматически конвертируются в Format 3 при скачивании через
`downloader.py`; GitHub-ссылки в тексте задачи обрабатываются автоматически.

> При скачивании задачи через `downloader.py` файлы `tests/N`, `tests/N.clue` и
> при необходимости `tests/N.type` создаются **автоматически** из ZIP-архива или
> HTML-таблицы в тексте задачи. Если ни ZIP, ни таблицы нет — папку `tests/`
> нужно заполнить вручную. См. [grader-workflow.md § Шаг скачивания задачи](grader-workflow.md#шаг-скачивания-задачи).

### Вердикты тест-кейсов

Полный набор — `Verdict` в `core/result.py` (6 значений); канон полей — [result-contract.md](../dev/result-contract.md).

| Вердикт | Значение |
|---------|----------|
| AC | Accepted — вывод совпал с ожидаемым |
| WA | Wrong Answer — вывод не совпал |
| TLE | Time Limit Exceeded — превышен таймаут |
| RE | Runtime Error — процесс завершился с ненулевым кодом |
| CANCELLED | Прогон отменён (async job `--serve` через `RunSpec.cancel_event`), а не по таймауту. |
| SANDBOX_VIOLATION | Под `--sandbox` нарушен лимит песочницы (память/процессы/размер вывода) — аддитивный вердикт, не ломающий AC/WA/TLE/RE. |

## Как сравнивается вывод

`AC` ставится, когда вывод решения совпал с ожидаемым **дословно**: обе стороны
разбиваются на строки и сравниваются поэлементно. Единственное послабление —
числа с плавающей точкой, и включается оно, только если дословное сравнение уже
не совпало **и** число строк с обеих сторон одинаково.

### Что прощается

| Что | Пример | Почему |
|---|---|---|
| Расхождение float за 9-м знаком | вывод `0.3333333333333333`, ожидание `0.333333333` | каждая строка округляется до 9 знаков (`round(x, 9)`) — но **только если знаков в выводе не меньше**, чем в ожидании, см. ниже |
| Разная запись одного числа | `1e-07` ↔ `0.0000001`, `1e+16` ↔ `10000000000000000.0` | после округления обе дают одну строку |
| Число внутри текста | `Ответ: 3.14159265358979` ↔ `Ответ: 3.141592654` | нормализуется каждое число в строке |
| `CRLF` в файлах тестов | файл сохранён в Windows | файлы читаются в режиме universal newlines |
| Отсутствие финального перевода строки | `expected_1.txt` не заканчивается на `\n` | завершающий перенос не образует отдельную строку |

> **Что считается переводом строки.** Только `\n`, `\r\n` и одиночный `\r` —
> то же правило, по которому Python читает текстовые файлы. Прочие управляющие
> символы (вертикальная табуляция, перевод страницы, `U+2028`) остаются
> **данными внутри строки**: вывод `a<VT>b` — это одна строка, и с ожиданием из
> двух строк он не совпадёт.

Версии и IP-адреса (`3.10.5`, `192.168.1.1`) под округление не попадают —
последовательность из нескольких точек числом не считается.

### Что не прощается

| Что | Пример |
|---|---|
| Пробел по краям строки | `hello ` (с пробелом в конце) против `hello` |
| Другой пробельный символ | табуляция или неразрывный пробел вместо обычного |
| Лишняя либо недостающая пустая строка | лишний `print()` в конце решения |
| Целое против дробного | `5` против `5.0`; `0.0` против `-0.0` |
| Расхождение внутри 9 знаков | `0.12345678` против `0.12345679` |
| **Знаков меньше, чем требует ожидание** | вывод `12.3` против ожидания `12.30` |
| Запятая как десятичный разделитель | `3,14` против `3.14` |
| Разные юникод-формы одной буквы | `й` (NFC) против `и` + комбинируемая бреве (NFD) |

> **Незначащие нули в ожидании — это требование формата, а не другая запись
> числа.** Задача «вывести с точностью до сотых» ожидает `12.30`, и вывод `12.3`
> её требование не выполняет, хотя величина та же. Раньше округление до 9 знаков
> стирало эту разницу и выдавало `AC` — а Stepik ту же отправку заворачивал:
> грейдер оказывался зеленее платформы ровно на той ошибке, ради которой его и
> запускали. Теперь толерантность действует, только когда знаков в выводе **не
> меньше**, чем в ожидании: `0.30000000000000004` против `0.3` по-прежнему `AC`,
> а `12.3` против `12.30` — `WA`. Разные формы записи (`1e-07` ↔ `0.0000001`)
> под правило не попадают: разрядность там не выражена.

> **BOM в файлах тестов больше не мешает.** «Блокнот» и Excel сохраняют UTF-8 с
> маркером порядка байтов, и раньше он оставался первым символом первой строки:
> в файле ожиданий давал `WA` верному решению, во входном — утекал в `stdin`, и
> верный код падал на `int(input())`, а в формате 3 ломал маркер `# TEST_1:`,
> из-за чего набор молча становился пустым («NO TESTS»). Теперь маркер порядка
> байтов срезается при чтении. BOM, **напечатанный самим решением**, значимым
> символом быть не перестал — сравнение его по-прежнему учитывает.

> **Файл тестов не в UTF-8** (например, cp1251 из «Блокнота») больше не роняет
> прогон трейсбеком и не обрывает пачку в режиме 2: нечитаемые байты заменяются,
> а предупреждение называет файл, байт и позицию. Заменённые символы почти
> наверняка дадут `WA` — пересохраните файл в UTF-8, предупреждение именно об
> этом и говорит.

> **Формат 3: края блока.** Пробелы внутри строк значимы во всех трёх форматах,
> в том числе по краям блока: фигура с отступами (ёлочка, таблица) сравнивается
> дословно. А вот **пустая** строка — как и строка из одних пробелов — в начале
> или конце блока `# TEST_N:` теряется: граница блока задаётся маркером, и
> отбивку перед следующим маркером от данных не отличить. Задачу, где пустая
> строка по краям ожидаемого вывода значима, задавайте форматом 1 или 2.

Поведение зафиксировано прогонными тестами
[`tests/test_output_comparison.py`](../../tests/test_output_comparison.py):
если таблицы выше разойдутся с ними, правы тесты.

## Ограничения и безопасность

**Threat model: решения запускаются БЕЗ полноценного sandbox на уровне ОС.**
Дочерний процесс имеет тот же доступ к файловой системе, сети и переменным
окружения, что и сам grader. Защита по времени выполнения есть всегда
(таймаут); на POSIX (Linux/macOS) есть ещё best-effort лимит памяти
(`GraderConfig.max_memory_mb`, по умолчанию 1024 МБ — `resource` через `RLIMIT_AS`
по pid после spawn); на Windows этого лимита нет (`resource` недоступен), решение
может использовать сколько угодно памяти. Ограничений диска или сети нет ни на
одной платформе. Запускай только доверенные решения (свои собственные или
скачанные из Stepik as-is) — grader не предназначен для проверки произвольного
untrusted-кода («нет sandbox на уровне ОС» задокументировано в
[`CLAUDE.md`](../../CLAUDE.md) и докстринге `core/runner.py`).

- **Режимы 1–3 (`grader_core.run_single_test` → `core/runner.py` `LocalRunner`):**
  решение запускается напрямую через `subprocess.Popen` (для function-mode — во
  временном wrapper-скрипте, импортирующем функцию решения). Единственная защита —
  `timeout=` у `proc.communicate()` (`grader_core.TIMEOUT_SECONDS`, по умолчанию 10 с).
- **Режим 4 (`core/microbench_runner.py`):** решения запускаются через
  subprocess (`python -c`) с `timeit.repeat`, защищены фиксированным
  `subprocess.run(timeout=60)`. Исходник передаётся через временный файл;
  `stdin` сбрасывается перед каждой итерацией, а `stdout` решения
  перенаправляется в `os.devnull` на время замера, чтобы его вывод не
  смешивался с числами-таймингами.
- **Microbench: локальный per-call таймаут отсутствует** — решение, зависающее
  внутри одного вызова (не в бесконечном цикле верхнего уровня), упрётся в
  общий 60-секундный `subprocess.run(timeout=60)` вокруг всего замера
  (5 повторов × N итераций), а не в индивидуальный лимит на итерацию.
  Сообщение об ошибке при таймауте указывает `number=<N>` (сколько итераций
  было в замере), чтобы хотя бы приблизительно понять масштаб зависания.
- **`--sandbox` работает и с `--serve`.** Опциональный
  `SandboxRunner` (`--sandbox`) изолирует и CLI-исполнение
  (режимы 1–4), и web: `stepik-grader --serve --sandbox`
  ставит `SandboxRunner` активным runner'ом до старта сервера, поэтому
  grade/playground/microbench изолируются разом. Без `--sandbox` web-сервер
  (как и CLI) исполняет код обычным `LocalRunner`'ом **без** изоляции — тот же
  дефолт «нет изоляции». Исключение: пошаговый трейс под `--sandbox`
  недоступен — трассировщик требует пакет проекта в исполняющем процессе
  (`core/tracer.py`). Если backend недоступен на машине (нет `bwrap` и т.п.),
  запуск завершается ошибкой, а не откатывается молча на незащищённое
  исполнение.

## Диагностика конфигурационных ошибок

| Симптом | Причина | Что делать |
|---|---|---|
| `⚠️ Тесты не найдены для: <name>` | нет папки `tests/` рядом с решением или неверный формат | создать `tests/` (см. [Формат тест-кейсов](#формат-тест-кейсов)) или скачать через `python -m stepik_grader.downloader` |
| Параметры из `pyproject.toml` не применились | опечатка в имени ключа или негодное значение | обе причины печатают предупреждение в stderr с именем ключа; сверить с таблицей [`[tool.stepik-grader]`](#toolstepik-grader-в-pyprojecttoml) |
| Лимит памяти не срабатывает | Windows (`resource` недоступен) | ограничение POSIX-only — см. [Ограничения и безопасность](#ограничения-и-безопасность) |
| Предупреждение об «осиротевших» файлах Формата 1/2 при Формате 3 | в `tests/` смешаны форматы; лишние файлы игнорируются | оставить один формат тест-кейсов на папку |
| Проблемы с токеном/авторизацией Stepik | `secrets.json`/OAuth | `python -m stepik_grader.diagnostic_stepik` — см. [installation.md](installation.md#работа-с-api-stepik-oauth) |
