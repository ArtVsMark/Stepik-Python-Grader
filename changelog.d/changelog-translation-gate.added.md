Гейт на непереведённые записи: `scripts/check_changelog_translated.py` считает запись подозрительной, если вне кода в ней нет ни одной кириллической буквы, — зеркало проверки «чистоты `en.json`», где перевод выдавала кириллица. Строгость разная по месту, и это главное: на PR предупреждение (запись в ветке может быть черновиком, и падать на состоянии работы значит блокировать чужие изменения), на релизе — отказ, потому что `CHANGELOG` и release notes уезжают в GitHub Release и на PyPI, где версия неперезаписываема. Проверяется ровно тот текст, который увидит внешняя аудитория: `extract_release_notes.py` теперь пишет файл, он же уходит в тело релиза и он же на гейт. Запись из одних идентификаторов проходит молча, а выпущенные секции `CHANGELOG` не судятся вовсе — до 1.10.0 записи писались по-английски, и это история, а не дефект. Место гейта в `verify` закреплено `check_workflow_guardrails.py`: вызов без `--strict` возвращает 0 и публикацию не остановит (#1290)
