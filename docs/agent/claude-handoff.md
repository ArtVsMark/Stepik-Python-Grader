# Очередь работ для Claude Code

> **Что это.** Порядок работ после крупного аудита: что за чем делать и почему
> именно в этом порядке. Заполняется, когда аудит выявил связанный пласт задач,
> который не выражается плоским списком issue (есть блокеры, «делать вместе»,
> «иначе фиксы недоказуемы»). Очищается, когда пласт разобран.
>
> **Чего здесь нет.** Отчётов «мы это сделали» — они в
> [`../CHANGELOG.md`](../../CHANGELOG.md). Критериев приёмки — они в самих GitHub
> issue. Списка открытых задач — он в `gh issue list` и устаревает за спринт,
> если продублировать сюда.

## Текущая очередь: разбор аудита 2026-07-30

Источник — [`../audit/2026-07-30-full-roles.md`](../audit/2026-07-30-full-roles.md)
и его эпик с подэпиками (`gh issue list --label epic`). Ниже — **только те шесть
пластов, где порядок обязателен**: общий файл, жёсткий блокер или «иначе фикс
недоказуем». Остальные 43 задачи аудита независимы, берутся в любом порядке и
живут в трекере, а не здесь.

Задачи названы по сути и файлу, а не по номеру: номера устаревают, а причина
порядка — нет. Рёбра: `→` жёсткий блокер · `⤳` мягкий порядок · `✓` независима.

### A. Корректность вердиктов — первым, до всего остального

```
прогонные тесты сравнения вывода (normalizers)
   → strip() ведущих пробелов (core/parsers.py)
   → детектор function-блоков (core/test_loader.py)
✓  печать возврата обёрткой (core/wrapper_builder.py) — параллельно
```

Тесты идут **раньше** фиксов, а не после: сравнение вывода сейчас не покрыто ни
одним прогонным кейсом, и правка `strip()` с равным успехом чинит ведущие
пробелы и ломает соседний сценарий — доказать будет нечем.

`parsers` перед `test_loader`, потому что оба разбирают формат 3: правка
детектора первой замаскирует дефект `strip()` — тест на ведущие пробелы начнёт
падать по другой причине, и разбор уйдёт не туда.

**Почему пласт вообще первый.** Всё остальное улучшает инструмент, который
выдаёт неверный вердикт: пока эти двое открыты, любая другая работа повышает
качество вокруг сломанного ядра.

### B. Guard раньше содержимого, которое он стережёт

```
guard'ы локалей (scripts/check_ui_locale_guardrails.py, check_locale_guardrails.py)
   → двуязычность пользовательских поверхностей
```

Чинить непереведённое до guard'а бессмысленно: он ходит по захардкоженному
списку JS-файлов, поэтому новый файл снова окажется вне проверки и регресс
вернётся молча — ровно так `feedback.js` не проверялся ни разу. Плюс
исправленный guard сам даёт полный список того, что чинить; составленный
аудитом вручную — заведомо неполон.

Правило шире одного случая: **«почини данные X» всегда после «почини guard,
который стережёт X»**.

### C. Песочница — один файл, порядок по зависимости

```
✓  сетевая изоляция на локальный listener (tests/test_sandbox_runner.py) — раньше всех
   stdin в отдельный поток → cancel_event в backend'ах → уборка внуков и частичный вывод
   ⤳ cwd, лимиты и временные файлы
```

Все правки, кроме первой, идут в `core/sandbox/_posix_common.py` и соседние
backend'ы — последовательно, иначе конфликты в одном файле.

Порядок содержательный: пока stdin пишется синхронно, прогон под `--sandbox`
виснет — и проверить отмену физически нечем, тест на `cancel_event` повиснет
вместе с прогоном. Уборка процессов требует уже рабочего цикла ожидания.

Тест изоляции — **раньше всех**: сейчас он бьёт во внешний IP и без интернета
проходит вхолостую, то есть сети безопасности у пласта нет вообще.

### D. Состояние и кодировки — общий файл

```
устойчивость чтения к не-UTF8 → склейка записи после обрыва
```

Оба трогают `core/stats.py`: сначала чтение, потом запись. В обратном порядке
правка `append` встанет на код, который вот-вот перепишется.

### E. Релиз — цена ошибки не откатывается

```
гейт тестов перед публикацией ⤳ пиннинг actions и права токенов
```

Оба правят `.github/workflows/release.yml`, поэтому вместе. Гейт важнее:
версия в PyPI неперезаписываема — это единственная ошибка в аудите, которую
нельзя откатить.

**Вне очереди по срочности:** запуск CI-агента посторонним (`claude.yml`,
метка `owner-action`). Ничего не блокирует и ничем не блокируется, но пока
задача открыта, агента с токеном владельца запускает любой человек из интернета.

### F. Web-поллер — общая механика

```
реакция на не-200 и перезапуск сервера ⤳ мелкие дефекты того же цикла
```

Оба чинят цикл опроса в `web/static/grade.js`. Порядок мягкий, но вместе —
иначе один и тот же цикл переписывается дважды.

---

**Незакрытые пробелы аудита** — не «доделки», а зоны, которые аудит признал
непроверенными: сравнение вывода в `normalizers.py`, инвентарь `skip`/`xfail`,
`tests_writer`/`task_page_parser`, отсутствие любых замеров производительности.
Если после пластов A–F останется бюджет, они важнее косметики.

Серверный трек по-прежнему не начат и держится roadmap-issue **#59**.

## Как заполнять после аудита

1. **Только связанные пласты.** Одна волна = одна причина держать порядок:
   общий файл, жёсткий блокер, «без этого фикс недоказуем». Плоский список
   независимых задач — в issue, не сюда.
2. **Формат волны:** заголовок с целью и релизом, под ним issue с пометкой типа
   ребра — `→` жёсткий блокер, `⤳` мягкий порядок (ради минимума переделок),
   `✓` предпосылка выполнена.
3. **Обоснование, а не пересказ issue.** Пишется то, чего в issue нет: почему
   этот порядок, что сломается при другом, где escape-hatch, если задача
   буксует.
4. **Проверки по фактическому коду.** Если аудит расходится с кодом (объём
   меньше заявленного, блокер уже снят) — фиксируй это здесь: план должен
   опираться на репозиторий, а не на текст issue.

## Как чистить по завершении

Волна разобрана — её запись **удаляется**, а не помечается «✅ выполнена».
Пометки о сделанном превращают доску очереди в журнал: именно так прежняя
редакция этого файла выросла до 336 строк отчётов о закрытых волнах. Если
разбор волны представляет исторический интерес, целиком перенеси её в
[`archive/`](../archive/README.md) отдельным файлом и оставь здесь пустое
состояние, как выше.

**Архив прошлых постановок:**
[`archive/claude-handoff-2026-07-15.md`](../archive/claude-handoff-2026-07-15.md)
— волны 1–6 плана 2026-07-15, разборы web-задач и указатели на
дизайн-контракты server mode.

## Общие правила для любой задачи

Полностью — в [`../CLAUDE.md`](../../CLAUDE.md) и
[`../CONTRIBUTING.md`](../../CONTRIBUTING.md): ветвиться от свежего `main`, PR — в
`main`; Python 3.12+ union-типы; `from __future__ import annotations`; `__all__`
в новых модулях; не добавлять зависимости без явного указания; не ломать
`--serve`, `/api/grade` и DAG без циклов; `pytest` + `ruff` + `mypy` зелёные
перед PR; запись в `CHANGELOG.md [Unreleased]`.
