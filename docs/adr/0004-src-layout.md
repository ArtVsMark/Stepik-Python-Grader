# ADR-0004 — Раскладка пакета: src-layout (`src/stepik_grader/`)

- **Связанный код/доки:** [pyproject.toml](../../pyproject.toml)

## Контекст

Изначально пакет и точки входа лежали в корне репозитория (`grader.py`,
`executor.py`, …). Плоская раскладка позволяет `import grader` прямо из корня —
**без установки пакета**. Это удобно на первый взгляд, но маскирует ошибки
упаковки: тесты и запуск бьют по локальным файлам в корне, а не по тому, что
реально попадёт в wheel. Забытый в `packages`/`package-data` модуль,
неправильный путь к данным, сломанная console-script — всё это «работает у меня
из корня», но падает у пользователя после `pip install`.

Проект распространяется как устанавливаемый пакет (`pip install -e .`,
console-script `stepik-grader`, запуск `python -m stepik_grader.X`). Нужна
гарантия: **то, что тестируется, = то, что ставится**.

## Решение

1. **Весь пакет живёт в `src/stepik_grader/`** (src-layout).
   `[tool.setuptools.packages.find] where = ["src"]`; корень репозитория не
   является import-путём пакета.
2. **Без root-shim'ов.** Никаких тонких `grader.py`/`executor.py` в корне,
   реэкспортирующих из пакета ради обратной совместимости — чистая миграция
   `git mv` с сохранением истории (issue #35, «clean src-layout rather than keep
   thin root shims»).
3. **Запуск и тесты — только против установленного пакета.** `pip install -e .`
   обязателен; входные точки — `python -m stepik_grader.grader` /
   `stepik-grader`. Прямого `python grader.py` из корня нет.
4. **Coverage меряется по `src/`** (`[tool.coverage] source = ["src"]`) — так
   охват считается для упакованного кода, а не для случайных корневых скриптов.

## Альтернативы

- **A. Плоская раскладка в корне (status quo до #35).** Плюс: запуск без
  установки. Минус: import-shadowing (локальный файл затеняет установленный
  пакет), тесты гоняют не то, что ставится, ошибки упаковки не ловятся до
  релиза. Отклонено.
- **B. src-layout + тонкие root-shim'ы для обратной совместимости.** Плюс:
  `python grader.py` продолжает работать. Минус: два пути импорта и их дрейф,
  shim'ы снова маскируют упаковку — тень основной цели миграции. Отклонено явно
  в #35.
- **C. src-layout, чистая миграция (выбрано).** Один канонический import-путь,
  упаковка проверяется самим фактом «тесты идут через установленный пакет».

## Последствия

**Положительные:**

- Невозможно случайно импортировать неустановленный пакет; тесты исполняют
  ровно то, что уйдёт в wheel.
- Ошибки упаковки (забытый модуль, `package-data`, entry point) всплывают сразу
  при `pip install -e .`, а не у пользователя.
- Чистый namespace: точки входа (`grader`/`cli`/`downloader`/`diagnostic_stepik`
  + `config`) на верхнем уровне пакета, внутреннее — в `core/`.

**Отрицательные / издержки:**

- `pip install -e .` обязателен перед запуском/тестами — нельзя «просто
  `python grader.py`»; это разово задокументировано в
  [installation.md](../installation.md).
- Разовая стоимость миграции `git mv` (выполнена в #35).

**Нейтральные:**

- Раскладка согласована с динамической версией (setuptools-scm, [ADR-0005](0005-dynamic-versioning.md))
  и mypy/ruff/coverage-конфигами, которые адресуют `src/stepik_grader`.
