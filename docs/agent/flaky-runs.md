# Журнал нестабильности прогонов

> Пишется механизмом, а не памятью: `python scripts/gh_rest.py rerun-failed
> <run-id> --why "<что мигнуло>"` дописывает строку сам и без `--why` не
> работает.

**Зачем.** Перезапуск не чинит — он меняет исход, не меняя причины. Прошло со
второго раза значит, что проверка зависит не только от кода, и это факт о
системе, который иначе теряется. Доля прогонов, потребовавших перезапуска, —
измеримая величина, и она не должна расти.

**Как читать.** Строка — один частичный перезапуск. Повторяющийся сюжет здесь
и есть кандидат в задачу: чинить надо причину, а не исход.

## Ручной перезапуск и автоматический — разные записи

В таблице ниже живут перезапуски, сделанные **человеком или окном**: там есть
кому написать `--why`, и без него команда не работает.

Автоматические перезапуски (`.github/workflows/rerun-flaky-checks.yml`) сюда не
попадают, и это осознанно: workflow не может дописать строку в файл — `main`
защищена, прямой push запрещён всем, включая GitHub Actions. Их след —
**summary прогона** самого workflow: что перезапущено, что не тронуто и почему.
Заводить ради этого коммит в `main` значило бы платить лишним прогоном CI за
каждую строку журнала.

Различать их всё равно нужно, и различает их граница возможностей механизма:

- **автоматический** перезапуск возможен только для проверок из закрытого
  списка `AUTO_RERUN` (`scripts/rerun_flaky_checks.py`) — сейчас там одно имя,
  `claude-review`, чей красный цвет означает осечку исполнения, а не дефект
  кода. Попытка ровно одна, и рядом не должно быть других красных;
- **ручной** перезапуск возможен для чего угодно — и именно поэтому требует
  `--why` и строки здесь. Обязательная проверка, прошедшая со второго раза, —
  самый ценный сюжет этой таблицы.

Растущая доля автоматических перезапусков читается по прогонам workflow: если
`claude-review` мигает каждый день, чинить надо его, а не перезапускать.
