## 🚀 Визионер

### Методика

Смотрел по коду, не по докам: `src/stepik_grader/core/` (runner.py, history.py, insights.py, tracer.py, error_glossary.py), `web/` (server.py, runs.py, insights_adapter.py), `cli/` (options.py, commands.py, `__init__.py` — ветка `--serve`/`--sandbox`), `pyproject.toml` (extras, entry points), `glossary/data/*.json` (посчитал статусы скриптом: 601 ready + 787 draft — сходится с фактами оркестратора), README, docs/server-mode.md, docs/audit-2026-07.md § 8 (прошлый «Визионер»). Прочитал тела открытых issue #59 и #151 через GitHub API. Проверил git-теги (9 релизов за 3 недели: v1.0.0 2026-06-24 → v1.8.0 2026-07-14) и авторство (фактически solo: владелец + CI-бот). Пакет публикуется на PyPI (docs/installation.md:41-52).

### Сильные стороны

1. **Ядро уже платформа-агностик.** `core/grader_core.py`, `core/runner.py`, `core/test_loader.py` не импортируют ничего Stepik-специфичного — привязка к платформе живёт только в `downloader.py`/`core/stepik_client.py`. Три формата тест-кейсов универсальны: грейдер уже сегодня — generic локальный IO-judge для Python, это просто нигде не продаётся.
2. **Фазы 0–2 server mode реально сделаны, а не нарисованы**: `Runner` Protocol + `LocalRunner` (`core/runner.py`), SandboxRunner MVP на 3 ОС (`core/sandbox/`), async job model `POST /api/v1/runs` (`web/runs.py`), стабильный контракт результата (docs/result-contract.md). Редкий случай, когда дизайн-доки отстают от кода в хорошую сторону.
3. **Горизонт 1 прошлого аудита выполнен за один релиз**: SQLite-история (`core/history.py`, WAL, миграции), таксономия падений + затухание (`core/insights.py`), правила PEP 8 (`rules/`), CLI+web витрины. Скорость исполнения — главный актив проекта.
4. **AI-native процесс разработки как конкурентное преимущество**: 9 релизов/3 недели с полной дисциплиной (CI-матрица 3 ОС, guardrail-скрипты, Conventional Commits). Solo-мейнтейнер с Claude Code двигается со скоростью маленькой команды.
5. **Готовые «якоря» для AI-фидбека уже в коде**: `failure_kind` (`core/insights.py`), единый резолвер подсказок (`core/error_glossary.py`), 601 ready-карточка глоссария (теперь двуязычная, PR #388), карточки правил, JSON-трейс исполнения (`core/tracer.py`). Контент против галлюцинаций создан — не хватает только канала.
6. **Дистрибуция и офлайн-first**: PyPI + pipx, полностью вендоренный web UI без CDN (`web/server.py:1-18`) — privacy-дифференциатор против Exercism/Codewars/LeetCode реален, а не декларативен.

### Находки

**V1. [high] Петля удержания разорвана на главной поверхности продукта.** `history.record_run()` вызывается только из CLI (`cli/commands.py:259,340,414,565`); web-слой (`web/viewmodels.py`, `web/runs.py`) не пишет историю вообще, при этом `web/insights_adapter.py` её *читает*. Плюс `record_history: bool = False` по умолчанию (`src/stepik_grader/config.py:62`). Итог: новичок, живущий в web UI (целевая аудитория), видит вечно пустой раздел «Подучить» — флайвил, ради которого строился весь эпик #342, выключен по умолчанию и физически не подключён к web-проверкам. Это главный стратегический баг v1.8.0.

**V2. [high] Фазы 3–4 server mode (#153/#154/#155) нереалистичны для solo и сейчас не нужны.** Accounts + PostgreSQL + multi-tenant контейнерный sandbox — это ops-бремя (хостинг, инциденты, GDPR/152-ФЗ, abuse), которое съест мейнтейнера; при этом на Windows сетевая изоляция отсутствует даже локально (docs/server-mode.md:98-110), т.е. фундамент фазы 3 не готов. Монетизационной гипотезы под сервер нет. Рекомендация: явно заморозить #153-155 как design-only (label `icebox`), ценность «сервера» добирать без сервера — файловый teacher mode (экспорт/импорт анонимных агрегатов класса, идея § 8 прошлого аудита, до сих пор не оформлена в issue).

**V3. [high] AI-фидбек (#59) не начат — а окно закрывается.** В коде нет ни одного LLM-вызова (grep по `openai|anthropic|llm` пуст). К 2026 «объясни, почему WA» — базовое ожидание: Copilot/Replit/Exercism (AI-ментор) это уже дают. Дешёвый путь без новых зависимостей: `requests` уже runtime-зависимость — BYOK-клиент к любому OpenAI-compatible endpoint (закрывает и облако, и локальные модели через ollama/llama.cpp тем же `base_url`), opt-in `--ai-hints`, промпт заякорен на `failure_kind` + diff + карточку правила/глоссария. Отдельно — MCP-сервер (extra `[mcp]` по прецеденту `[watch]`/`[lint]`, pyproject.toml:25-46): tools `grade_solution`/`get_insights`/`lookup_term` превращают грейдер в инфраструктуру для Claude Code/Copilot-агентов студента — канал дистрибуции, где конкурентов в этой нише нет.

**V4. [medium] Мультиплатформенность из #59 (Codeforces/LeetCode) — низкая ценность за высокую цену.** Главный дифференциатор проекта — автоскачивание тестов — не переносится: LeetCode тесты не публикует, Codeforces показывает усечённые («...»). `PlatformPlugin.download_tests()` там нечем наполнить. При этом generic-режим («любая папка input/expected») уже работает — не хватает только витрины в README/доках. Рекомендация: деприоритизировать платформенные плагины на 2-3 релиза, вместо этого задокументировать generic-использование.

**V5. [medium] Позиционирование сужает потолок: RU-only витрина + бренд одной платформы.** README целиком на русском и привязан к 5 курсам «Поколение Python»; имя пакета — `stepik-python-grader` при платформа-агностик ядре (V4). Глоссарий уже двуязычный (`{ru,en}`, PR #388) — сигнал амбиции, но воронка (README, docs/) остаётся русскоязычной. Ниша против Exercism/Codewars правильная — «локальный privacy-first компаньон к чужому курсу», не хостинг контента — но она работает и для англоязычных MOOC. Минимум: английский README-раздел (quick start + generic mode). Rename пакета — не сейчас (дорого, брендовая история), но зафиксировать решение в ADR.

**V6. [medium] Риск распыления solo-мейнтейнера — самый недооценённый.** Одновременно открыты: контент-конвейер глоссария (787 драфтов, волны B1-B6, ~7 волн по темпу #371 ≈ 45-110 карточек/PR — кварталы ручной работы), server-эпики (#151-155), генеральный эпик #97, roadmap #59 с 4 направлениями. Плюс `app.js` вырос до 2468 строк vanilla-JS (web/static/app.js) — каждый новый раздел дороже предыдущего. Контент-конвейер стоит частично автоматизировать: скрипт LLM-черновиков с обязательным прогоном примеров кода (валидация `# → результат` уже практикуется в #371 вручную) + human review, иначе глоссарий съест продуктовые релизы.

**V7. [low] Монетизация не заявлена — и это нормально, но нужно сказать вслух.** MIT, нет FUNDING.yml (`.github/` — только templates/badges/workflows), ниша — RU-новички конкретной линейки курсов. Реалистичная стратегия на 2-3 года: open-source навсегда, GitHub Sponsors как «чаевые», B2B2C-эксперимент через file-based teacher mode (V2) для репетиторов/школ — единственный сегмент с платёжеспособностью, не требующий сервера. Любой pivot в платный hosted-грейдинг конкурирует со Stepik на его же поле — не надо.

**V8. [low] «Архив побед»/экспорт прогресса из горизонта 1 прошлого аудита так и не сделан** — единственный невыполненный пункт § 8. История в SQLite уже есть (`core/history.py`), экспорт в Markdown/HTML («поделиться с ментором/в резюме») — дешёвая вирусная петля без сервера; уместен после V1.

### Рекомендации: ближайшие 2 релиза, чтобы не закопаться

**v1.9 — «замкнуть петлю» (продукт, не контент):** (1) web-проверки пишут историю + first-run consent-переключатель в «Настройках» вместо молчаливого default-off (V1); (2) экспорт прогресса Markdown/HTML (V8); (3) английский quick start + generic-mode раздел README (V5); волна B2 глоссария — фоном, не блокером релиза.

**v2.0 — «AI-канал»:** (1) ADR-0002 «Стратегия AI-интеграции» (BYOK vs MCP vs локальные модели — выбор: OpenAI-compatible BYOK на `requests` + MCP-extra как второй канал); (2) MVP `--ai-hints` с якорями на карточки; (3) заморозка #153-155 с честным re-label; (4) конвейер LLM-черновиков карточек для волн B3-B6.

**Чего НЕ делать в 2026:** hosted server mode (фаза 4), платформенные плагины Codeforces/LeetCode, переписывание фронтенда на фреймворк, rename пакета.
